# S11-00 — замер: подхватывается ли команда из `.claude/commands` через посимвольный симлинк

Тип агента: **`adw-prober`**
Слой: **—** (платформенный замер)
Происхождение: решение человека 2026-08-09, `plan/FINDINGS.md`, секция «Решения человека, 2026-08-09 —
петля разбора и интервью», строка «Форма команд зависит от замера».

**Вопрос.** `.claude/commands` в этом репозитории — симлинк на **каталог** `plugins/adw/commands`, и
эта форма замеренно работает: команды видны под короткими именами (`plan/INSTALL-REHEARSAL.md` §6).
Проходу S11 нужна другая форма — реальный каталог, внутри которого посимвольные симлинки на четыре
файла команд цикла плюс реальные локальные файлы. Неизвестно, читает ли платформа командный файл
**через файловый симлинк**. Молчание здесь правдоподобно: неверная форма имени скилла в `skills:`
замеренно игнорируется без единого слова наружу (`plan/PLATFORM.md`), и от регистрации команд стоит
ожидать того же характера.

Читать сначала:

- `plan/PLATFORM.md` — шапка и легенда: формат, в котором записываются вопросы и замеры, и как
  выглядят девять существующих вопросов;
- `.claude/agents/adw-prober.md` — раздел про дискриминирующую пробу: проба, проходящая и при
  работающей фиче, и при неработающей, не доказывает ничего.

## Задача

Всё пробное — в скретч-каталоге сессии, вне этого репозитория. В нём:

1. **Проект-пустышка**: каталог, внутри `.claude/commands/` как **реальный** каталог. В каталоге:
   - `real.md` — реальный файл-команда: фронтматтер с `description`, тело — инструкция ответить
     ровно строкой `PROBE-REAL-OK` и ничего больше;
   - `linked.md` — **симлинк** на файл, лежащий вне `.claude/` (например, `bodies/linked-body.md`
     рядом с пустышкой), тело того файла — инструкция ответить ровно строкой `PROBE-LINK-OK`.
   Строки-маркеры не должны встречаться нигде, кроме тел команд, — иначе проба не дискриминирует.
2. **Контроль**: из корня пустышки вызвать `/real` неинтерактивно (`claude -p "/real"` или равное).
   Если реальная команда в этом режиме не вызывается вовсе — проба не дискриминирует, и итог по
   симлинку — `НЕ ПРОВЕРЕНО` (см. ниже), а не догадка.
3. **Замер**: тем же способом вызвать `/linked`. `PROBE-LINK-OK` в ответе при живом контроле —
   команда прочитана через симлинк; отказ или пустота при живом контроле — не прочитана.
4. На каждом замере — версия (`claude --version`) и дата.

Если неинтерактивный режим не дал контроля, честный итог — `НЕ ПРОВЕРЕНО`, с оговоркой «в
интерактивной сессии не проверялось» и с описанием добивающего эксперимента: перестроить каталог,
рестартовать интерактивную сессию, посмотреть, видны ли все команды. Это полный и приемлемый ответ.

## Deliverables

Десятый вопрос в `plan/PLATFORM.md` — в формате файла: вопрос, команды, реальный вывод, версия,
дата, вердикт `ЗАМЕРЕНО` (работает / не работает) либо `НЕ ПРОВЕРЕНО`. Больше ничего.

## Границы

- В этом репозитории не трогать ничего, кроме `plan/PLATFORM.md`.
- `.claude/commands` этого репозитория **не перестраивать** — это S11-02, и она ждёт твоего вердикта.
- Пробные артефакты — только в скретче; в репозиторий не попадает ни один.
- Не чинить найденное по дороге: находка идёт в отчёт, пишет её главная сессия.

## Проверка

Прогнана на нетронутом дереве до отправки задачи; ответ «до» назван у каждой строки.

```bash
git diff --stat -- plan/PLATFORM.md
# до: пусто. После: один файл
git status --porcelain -- .claude/
# до: пусто. После: пусто — каталог команд не тронут
rtk proxy find plugins/adw -name '*.py' -o -name '*.sh' -o -name 'hooks.json' -o -name 'anchors.json'
# до: пусто. После: пусто — красная линия 2
```

## Что скажет warden

- `plan/PLATFORM.md` несёт команды и реальный вывод, а не «должно работать»: слова-заключения без
  замера — провал роли, и `НЕ ПРОВЕРЕНО` ценнее правдоподобной догадки;
- проба дискриминирует: маркеры из **тел** команд, контроль и замер дали разные строки;
- `.claude/commands` не тронут, пробных артефактов в дереве нет;
- вердикт одной строкой, и он один из трёх законных.
