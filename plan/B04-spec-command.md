# B04 — команда `/adw:spec`

Тип агента: **`adw-builder`**
Слой: **адаптер** (файл команды), тело — проза, переносимая
Зависит от: B03

Читать сначала:
- `WORKFLOW.md` §6 (`/adw:spec`), §3 и §3.1 (форматы, глубины, пять триггеров), §2 (нарезка),
  §4 (гринфилд как вырожденный браунфилд)
- `plugins/adw/templates/` — результат B03
- `plugins/adw/commands/commit.md` — образец того, как в этом репозитории выглядит файл команды

## Задача

Интерактивная команда: интервью с человеком → `spec.md` + `criteria.md` на новой ветке.
Единственная команда, где решения принимает человек, поэтому она обязана **спрашивать, а не
догадываться** там, где ответ меняет работу.

## Deliverables

`plugins/adw/commands/spec.md`, с фронтматтером (`description`, `argument-hint`) и телом-прозой:

1. **Ориентация.** Прочитать `specs/` и код. Есть ли хоть один capability-файл — это и есть весь
   ответ на «гринфилд или браунфилд» (§4), никакого флага.
2. **Аллокация номера.** `NNN = max(существующих каталогов в specs/changes/ ∪ тегов change/*) + 1`.
   Формат идентификатора — `NNN`.
3. **Интервью.** `AskUserQuestion` по неоднозначностям. Предложить глубину S/M/L, решает человек.
4. **Пять структурных триггеров §3.1.** Прогнать явно и **сказать человеку результат**: сработал
   или нет и какой именно. Сработал — вопрос человеку, при нужде с исследованием кода через
   **встроенные** `Explore` / `Plan`; результат в секцию `Design`.
5. **Запись.** `spec.md` + `criteria.md` из шаблонов B03. Ветка `change/NNN`.
6. **Выходной контроль — человеком, не скриптом.** Перечислить проверки §6: критерий называет
   наблюдаемый артефакт; слова-маркеры расплывчатости (`корректно`, `правильно`, `works`,
   `как ожидается`) — переписать; `Verification` отвечает на «как доказать»; хотя бы один критерий
   проверяем через живое приложение. Не прошло — не писать спеку, а вернуться к вопросу.
7. **Первое изменение проекта** — вертикальный срез с одним сквозным критерием (§4). Сказать это
   человеку явно, если `specs/` пуст.
8. **Язык.** Спека пишется на языке диалога с человеком. Команда сама — по-английски.

## Границы

- Не писать тестов, кода, `Makefile`. Команда пишет только `spec.md` и `criteria.md`.
- Не диспатчить `test-author` / `implementer` / `evaluator` — это `/adw:build`.
- Не заводить своего исследовательского агента: только встроенные `Explore` / `Plan`.
- Не добавлять флагов режима (`--greenfield`, `--brownfield`) — §4 их запрещает.
- Не проверять критерии скриптом или регуляркой в файле команды: выходной контроль — человеком.

## Проверка

- Файл существует, фронтматтер парсится, `description` описывает команду одной строкой.
- Грепом: нет `--greenfield`, нет `--brownfield`, нет имён скриптов, нет `Task(` с ролевыми
  агентами цикла.
- Присутствуют все пять триггеров §3.1, дословно по смыслу.
- Присутствует правило аллокации `NNN`, включая учёт тегов.
- Присутствует список слов-маркеров расплывчатости.
- Присутствует правило «хотя бы один критерий через живое приложение».
- Тест переносимости: тело читается как инструкция для любого агента, а не для Claude Code
  специально (кроме двух явно названных встроенных агентов).

## Что скажет warden

- Флаг режима гринфилд/браунфилд → ОТКЛОНИТЬ (§4: режимов нет, это результат чтения).
- Регулярка/скрипт для проверки формулировок критериев → ОТКЛОНИТЬ (бюджет ноль; §6 говорит
  «человеком, не скриптом»).
- Своя обёртка-агент вокруг исследования кода → ОТКЛОНИТЬ (§3.1: встроенные `Explore` / `Plan`).
- Секция `Design` сделана обязательной для M/L → ОТКЛОНИТЬ (§3.1: по триггеру, не по глубине).
- Команда начала диспатчить цикл → ОТКЛОНИТЬ, это B05.
