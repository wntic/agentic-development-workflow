# S13-01 — миграция реестра: `plan/findings/`, legacy-файл, снос `FINDINGS.md`

Тип агента: **`adw-builder`**
Слой: **дев-запись**
Происхождение: решение человека 2026-08-09, `plan/FINDINGS.md`, секция «Решения человека, 2026-08-09 —
реестр по источникам, снос HISTORY.md», буллеты «Файл на источник», «Нумерация», «Миграция».

**Что это за задача и чего она не делает.** Реестр переезжает на модель дельт: файл на
событие-источник, удаляемый после исполнения решений. Эта задача выполняет **миграцию хранилища** —
переносит открытые записи в `plan/findings/legacy.md` и удаляет `plan/FINDINGS.md`. Она **не** правит
ни одной записи по содержанию, не решает ни одной находки и не трогает никакие другие файлы: указатели
на реестр по дереву — задачи S13-02…S13-04 и главной сессии.

Читать сначала:

- секция решений, названная выше, — целиком (она в конце `plan/FINDINGS.md`);
- шапка `plan/FINDINGS.md` — чтобы понять форму записи и форму строки диспозиции (`- **F-N → …`),
  которыми определяется «открытость»; в новый файл шапка **не** переезжает.

## Задача

**1. Каталог `plan/findings/` и файл `plan/findings/legacy.md`.** В него переезжают **дословно,
байт-в-байт, со своими F-номерами** тела 74 открытых записей. Список зафиксирован решением человека
(снят командой ORIENT §5 на 2026-08-09, до начала S13):


Тело записи — от её строки `## F-NNN · …` до начала следующего заголовка `## ` или разделителя `---`
(не включая их). Извлечение делай механически (awk/sed по диапазонам заголовков), не перенабором.
Шапку legacy-файла не сочиняй: две строки — «Открытые записи замороженной серии F, перенесены из
`plan/FINDINGS.md` 2026-08-09 (S13-01). Формат и правила — `plan/ORIENT.md` §5; серия заморожена на
F-284, новые находки живут файлами на источник.» — и дальше сразу тела.

**2. Снос `plan/FINDINGS.md`** тем же ходом (`git rm` не нужен — файл просто удаляется, коммит за
главной сессией). Всё непереехавшее — закрытые тела, решения, шапка — остаётся в git-истории, и это
прямое содержание решения.

## Deliverables

`plan/findings/legacy.md` (74 тела + две строки шапки-указателя), удалённый `plan/FINDINGS.md`.
Больше ничего.

## Границы

- Ни одна запись не правится по содержанию: ни заголовки, ни классы, ни «Решение отложено до» —
  дословный перенос. Обнаруженное по дороге — в отчёт, не в правку.
- Никакие другие файлы не трогаются: ни `ORIENT`, ни `INDEX`, ни `CLAUDE.md`, ни роли — у них свои
  задачи в этой же волне.
- `plan/findings/README.md` не создаётся — дом формата `ORIENT` §5, решением человека.

## Проверка

Прогнана на нетронутом дереве до отправки задачи; ответ «до» назван у каждой строки.

```bash
rtk proxy grep -c '^## F-' plan/findings/legacy.md
# до: файла нет, exit 2. После: 74
rtk proxy grep -o '^## F-[0-9]*' plan/findings/legacy.md | sort -u | wc -l
# до: файла нет. После: 74 — все номера различны
test -f plan/FINDINGS.md && echo ALIVE || echo GONE
# до: ALIVE. После: GONE
rtk proxy grep -c '^## F-197\b\|^## F-284 ' plan/findings/legacy.md
# до: файла нет. После: ≥1 на каждый край полосы (первая и последняя записи переехали)
git status --porcelain -- plugins/ .claude/ CLAUDE.md HISTORY.md WORKFLOW.md plan/ORIENT.md plan/INDEX.md
# до и после: без изменений от этой задачи (следы параллельных задач волны — не твои и не трогаются)
```

## Что скажет warden

- перенос дословный: выборочная сверка тел (минимум три записи, включая края полосы) против
  git-версии `plan/FINDINGS.md` — побайтово, кроме неизбежного отсутствия того, что не переехало;
- ровно 74 заголовка, номера уникальны, ни одного не из списка;
- никакой новой шапки-машинерии в legacy-файле — две строки указателя и тела;
- `FINDINGS.md` удалён, других файлов дифф задачи не касается.
