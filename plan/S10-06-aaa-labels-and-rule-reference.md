# S10-06 — шаблоны теряют AAA-метки, а ссылка на правило перестаёт быть номером

Тип агента: **`adw-builder`**
Слой: **ядро** (`plugins/adw/skills/test-principles/SKILL.md`,
`plugins/adw/skills/test-application-handler/SKILL.md`)
Происхождение: решения человека 2026-08-05, `plan/FINDINGS.md`, секция «Решения человека, 2026-08-05 —
раунд 4: каталог скиллов», строки **F-130** и **F-174**.

Читать сначала:
- в `plan/FINDINGS.md` — тела **F-130** и **F-174** заголовочным грепом
  (`rtk proxy grep '^## F-' plan/FINDINGS.md`, потом читать только эти две записи), и обе строки
  диспозиции в названной секции;
- `plugins/adw/skills/test-principles/SKILL.md` — шаблон AAA (метки на строках 158, 162, 165), блок
  `Rules` под ним (правило 1 на строке 172), и ссылка на строке ~129 («`-W error`, Reliability rule 9»);
- `plugins/adw/skills/test-application-handler/SKILL.md` — шаблон теста хендлера, метки на строках 45,
  49, 52;
- `plugins/adw/skills/python-style/SKILL.md`, раздел про комментарии (~272) — правило, которому метки
  противоречат. **Читать, не править:** этот файл принадлежит задаче S10-07.

Основание замерено:

```bash
rtk proxy grep -rn '^ *# \(Arrange\|Act\|Assert\)$' plugins/adw/skills/
# шесть строк: test-application-handler:45,49,52 и test-principles:158,162,165
cd ~/Projects/adw-rooms && rtk proxy grep -rn --include='*.py' '^[[:space:]]*# \(Arrange\|Act\|Assert\)\b' tests
# ноль — агенты эти метки не копируют
```

То есть шаблоны шипят разметку, которую правило про комментарии в теле теста запрещает («a comment that
is not a non-obvious *why* → stop»), и которую никто не использует.

## Задача

**Часть 1 — метки уходят из шаблонов (F-130).** Шесть строк удаляются, пустые строки между блоками
остаются на местах: разделение блоков держится на них, и правило 1 это уже говорит.

Правило 1 `test-principles:172` теряет скобку, называющую метки опцией, и остаётся требованием пустых
строк. Причина, которую надо назвать в самом правиле одним оборотом: структурная метка — не «почему», а
`python-style` требует от комментария в теле теста именно «почему». Оставить скобку значило бы держать в
каталоге две инструкции, одна из которых разрешает то, что другая запрещает.

**Часть 2 — ссылка называет правило словами (F-174).** На строке ~129 `(-W error, Reliability rule 9)`
становится ссылкой по существу правила, а не по его номеру, например
`(-W error — a warning is a failure, Reliability rules)`. Текст правила 9 (`test-principles:203`) —
«A warning is a failure, not a line in the tail of the output» — и формулировка ссылки берётся из него,
а не выдумывается.

## Deliverables

Два файла. В `test-application-handler` — три удалённые строки. В `test-principles` — три удалённые
строки, переписанное правило 1 и переписанная ссылка. Больше ничего.

## Границы

- **Только эти два файла.** `python-style` — задача S10-07, `conventions` — S10-08. Не заходи.
- **Пустые строки между блоками AAA не трогать** — они и есть механизм разделения после ухода меток.
  Удаление метки не должно склеить два блока в один.
- **Ни один `# Arrange` в прозе не трогать**, если он там есть как *упоминание* формы, а не как строка
  шаблона: греп из «Основание» матчит только строку целиком (`^ *# Arrange$`), и предмет правки — ровно
  его выдача.
- **Нумерацию Reliability rules не менять** — F-174 про ссылку, а не про нумерацию; перенумерация
  сделала бы ссылки в других файлах ложными, что и есть предмет находки.
- **Правило про комментарии не переписывать** — оно верно как есть, и живёт в другом файле.
- Не чинить найденное по дороге — находка идёт в `plan/FINDINGS.md`, и пишет её главная сессия.

## Проверка

Прогнана на нетронутом дереве до отправки задачи; ответ «до» назван у каждой строки, чтобы зелёное
после правки означало правку, а не исходное состояние.

```bash
git diff --stat -- plugins/adw/skills/test-principles/ plugins/adw/skills/test-application-handler/
# до: пусто. После: ровно два файла
rtk proxy grep -rn '^ *# \(Arrange\|Act\|Assert\)$' plugins/adw/skills/
# до: шесть строк. После: пусто
rtk proxy grep -c '^1\. \*\*Blank lines separate the three blocks' plugins/adw/skills/test-principles/SKILL.md
# до: 1. После: 1 — правило на месте, переписано его продолжение, а не заголовок
rtk proxy grep -n 'Reliability rule 9' plugins/adw/skills/test-principles/SKILL.md
# до: одна строка (~129). После: пусто
rtk proxy grep -c '^9\. \*\*A warning is a failure' plugins/adw/skills/test-principles/SKILL.md
# до: 1. После: 1 — само правило не тронуто, только ссылка на него
rtk proxy find plugins/adw -name '*.py' -o -name '*.sh' -o -name 'hooks.json' -o -name 'anchors.json'
# до: пусто. После: пусто — красная линия 2
```

## Что скажет warden

- **два файла, не больше** — `python-style` и `conventions` в диффе отсутствуют;
- **исключения в правило не заведено** — метки убраны, а не легализованы: это прямой довод диспозиции
  F-130, и он же довод F-139 в той же секции;
- **пустые строки на местах** — блоки AAA по-прежнему разделены;
- **правило 9 не тронуто, тронута ссылка на него** — нумерация Reliability rules та же;
- **числа рядом с командами** — каждая строка «Проверки» несёт ответ «до» и ответ «после», и оба
  воспроизводятся её собственной командой (правило раунда 1, F-156).
