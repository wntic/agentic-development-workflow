# S05-02 — легенда `PLATFORM.md` и дата, которая врёт про весь файл

Тип агента: **`adw-builder`**
Слой: **дев-запись** (`plan/PLATFORM.md`) — не шипится
Происхождение: решение человека **2026-08-02**, `plan/FINDINGS.md`, секция
**«Решения человека, 2026-08-02 — интервью по открытым находкам»**, **круг 3**.

Читать сначала:
- `plan/FINDINGS.md`, круг 3 секции интервью — контракт задачи, включая **предложение**, которое
  человек не выбирал (см. Границы)
- записи **F-75** и **F-76**
- `plan/PLATFORM.md` шапку и легенду (строки 1–12) и **все** заголовки разделов — правишь шапку,
  легенду и датировку разделов

## Задача

Две правки в одном файле, обе про то, что читатель не может понять срок годности факта.

**Легенда не покрывает наблюдение на настоящей нагрузке.** Пометок три: `ЗАМЕРЕНО` («команда
запущена, вывод наблюдён и приведён»), `ИЗ ДОКОВ`, `НЕ ПРОВЕРЕНО`. Раздел про ошибку 529 снят на живом
прогоне 002 и по требованию не воспроизводится — команды у него нет и быть не может. Читатель либо
построит на записи эксперимент, который не поставится, либо снимет её как нарушение легенды.

**Шапка датирует весь файл 2026-07-29**, а внутри лежат замеры от 30 июля, 1 и 2 августа. Часть
разделов несёт дату внутри текста, часть — не несёт вовсе.

## Deliverables

Один файл, две правки.

### 1. Формулировка `ЗАМЕРЕНО` расширяется, F-75

Пометка покрывает **и** наблюдение на настоящей работе с приведённым выводом, а не только запущенную
команду. **Четвёртая пометка не заводится** — это решено явно: различие «воспроизводится / не
воспроизводится» остаётся видимым из текста самой записи, а лишняя сущность в легенде стоит дороже.

Проверь заодно, что разделы, снятые с настоящей нагрузки (529 посреди диспатча; подтверждение
вопроса 8 на настоящей нагрузке), под новой формулировкой **законны без правки их тела**. Если
какой-то не подпадает — это находка, а не повод расширять формулировку дальше.

### 2. Дата уходит из шапки в разделы, F-76

В шапке остаются версия и правило «факт о платформе без версии — факт с неизвестным сроком годности».
Дата из шапки снимается, и каждый раздел несёт свою.

Разделы, которые дату уже несут, не трогать. Тем, у которых её нет, проставить **2026-07-29** — это
дата, под которой они и были написаны; она сегодня стоит в шапке и покрывает их. Не выдумывать дат:
если по разделу непонятно, когда он снят, оставь как есть и запиши это в отчёт.

## Границы

- **Только `plan/PLATFORM.md`.**
- **Пометку `НАБЛЮДЕНО` не заводить** — решение отвергло её явно.
- **Предложение из круга 3 не исполнять.** В решении записано предложение главной сессии дописать в
  расширенную формулировку «причина наблюдаемого не называется без замера». Человек его **не
  выбирал**, значит его в диффе быть не должно. Это прямой случай правила из F-78: правка, держащаяся
  только на ненайденном решении, — остановка, а не исполнение.
- **Содержание разделов не переписывать.** Правятся легенда, шапка и датировка; выводы замеров —
  нет.
- **Пометки `НЕ ПРОВЕРЕНО` остаются на месте**, их семь и они несут свои эксперименты. Ни одну не
  закрывать и ни одного эксперимента не ставить: это отдельное решение, и оно уже принято как «замер
  не ставить» (F-60, круг 3).
- Не чинить найденное по дороге.

## Проверка

```bash
git status --short                                        # ровно один файл
rtk proxy grep -n 'Дата замера: 2026-07-29' plan/PLATFORM.md    # пусто — из шапки дата ушла
rtk proxy grep -c 'НАБЛЮДЕНО' plan/PLATFORM.md            # 0
rtk proxy grep -c 'НЕ ПРОВЕРЕНО' plan/PLATFORM.md         # столько же, сколько было до правки
rtk proxy grep -n '2.1.220' plan/PLATFORM.md | head -3    # версия в шапке осталась
rtk proxy find plugins/adw -name '*.py' -o -name '*.sh' -o -name 'hooks.json'   # пусто
```

Плюс чтением: у каждого раздела с замером видна дата — своя или проставленная; легенда по-прежнему
называет три пометки и ни одной больше.
