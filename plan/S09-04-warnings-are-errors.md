## Задача

**Девятое правило в разделе «Reliability rules».** Существо: предупреждение — это провал теста, а не
строка в хвосте вывода. `[tool.pytest.ini_options]` несёт `filterwarnings`, первым элементом
`"error"`, и это часть определения «зелёного» — не отдельная команда и не отдельный прогон.

Правило обязано сказать три вещи, потому что без любой из них оно неисполнимо:

1. **что включается** — `filterwarnings = ["error", …]` в `[tool.pytest.ini_options]`, то есть там же,
   где уже живут `asyncio_mode` и `markers`;
2. **как записывается исключение** — это цена, названная в решении человека заранее: политика
   «всё в ошибку» делает красной первую же `DeprecationWarning` **чужой** библиотеки, которую проект
   починить не может. Исключение — строка `"ignore:<текст>:<Категория>:<модуль>"` следом за `"error"`,
   и она **несёт причину рядом**: чьё предупреждение, почему проект не может его убрать и что снимет
   исключение. Исключение без причины — это выключенное правило;
3. **что исключение не годится для своего кода** — предупреждение из `src/` чинится, а не глушится.
   Это тот же водораздел, что у `noqa` в `conventions`: подавление законно только на чужой границе.

Форма — один пронумерованный пункт (девятый) в том же стиле, что восемь существующих: тезис жирным,
затем одно-два предложения. Если исключение требует больше, чем помещается в пункт, **вторая строка
идёт туда же**, а не в новый раздел: раздел «Reliability rules» — это список, и он им остаётся.

**Строку 129 привести в соответствие.** Сегодня она говорит «under `-W error` a failure» как о
гипотетическом режиме. После правки режим — норма проекта, и формулировка «под `-W error`» становится
условной там, где условия больше нет. Правка минимальная: снять сослагательность, не переписывая пункт
про регистрацию маркера.

**Hard stop не добавляется.** Раздел `## Hard stops` останавливает автора теста; здесь останавливает
конфигурация, и второй формы у одного правила быть не должно.

## Проверка

```bash
git diff --stat -- plugins/adw/skills/                       # ровно один файл
rtk proxy grep -n 'filterwarnings' plugins/adw/skills/test-principles/SKILL.md
rtk proxy grep -n '^9\. ' plugins/adw/skills/test-principles/SKILL.md      # ровно одна строка — новый пункт
rtk proxy grep -c '^[0-9]\. ' plugins/adw/skills/test-principles/SKILL.md  # 15 (до правки было 14)
rtk proxy grep -n 'W error' plugins/adw/skills/test-principles/SKILL.md    # строка ~129 приведена
rtk proxy awk '/^## Hard stops/,0' plugins/adw/skills/test-principles/SKILL.md | rtk proxy grep -c '^- '
# 9 — hard stops не тронуты
rtk proxy find plugins/adw -name '*.py' -o -name '*.sh' -o -name 'hooks.json'   # пусто
```

Две оговорки к числам, обе замерены на дереве **до** правки, и обе о том, что голая команда считает
**не то**, о чём утверждение. `^[0-9]\. ` матчит нумерованные пункты **всего файла** — сегодня их 14 в
трёх разделах (conftest-иерархия, AAA, Reliability rules), поэтому правильный итог 15, а не 9: девять —
это пункты одного раздела, и команды на один раздел у нас нет. По той же причине hard stops считаются
**через `awk`, срезающий файл от их заголовка**, а не грепом `^- ` по всему файлу: дефисных пунктов в
файле 31, и 9 из них — только в последнем разделе. Первая редакция этой секции несла оба числа
неверными; они пересчитаны.

Плюс чтением: пункт называет форму исключения и требование причины; нигде не перечислены конкретные
библиотеки.

## Что скажет warden

  превращается в выключенную.
