# B06 — команда `/adw:accept`

Тип агента: **`adw-builder`**
Слой: **адаптер** (файл команды), тело — проза, переносимая
Зависит от: B03

Читать сначала:
- `WORKFLOW.md` §6 (`/adw:accept`), §2 (живая спека, удаление дельты), §3 (провенанс инвариантов)
- `plugins/adw/templates/capability.md` — результат B03
- `plugins/adw/skills/CONVENTIONS.md` — на случай вопросов о нарезке

## Задача

Принятие изменения: дельта вливается в живую спеку, человек читает diff, ветка мержится, каталог
дельты удаляется. Это **единственный штамп человека** во всём воркфлоу, поэтому команда обязана
подать ему на проверку ровно то, что он должен увидеть, и не больше.

## Deliverables

`plugins/adw/commands/accept.md`, с фронтматтером и телом-прозой:

1. **Предусловия.** Все критерии `[x]` или `[m]`; `make check` зелёный на ветке; `verdict.md`
   существует. Каждый `[m]` — с причиной в вердикте. Не выполнено — остановка.
2. **Вливание.** Операции дельты — в описание capability-файла; каждый закрытый критерий — в
   инвариант **с провенансом** `*(verified by: <test_id>)*` либо `*(MANUAL)*`. Нет capability-файла
   (первое изменение) — создаётся из шаблона.
3. **Multi-target.** `Affects` называет несколько файлов — распределение инвариантов **предлагает**
   команда, **утверждает человек**. Не сваливать всё в первый файл.
4. **Порог нарезки.** После вливания файл перевалил ~300 строк — сказать человеку и предложить
   резать (§2). Не резать самостоятельно.
5. **Два diff'а человеку, и оба обязательны:**
   - diff вливания в `specs/<capability>.md`;
   - `git diff <baseline>..HEAD -- tests/` — правки тестов после baseline (§5).
   Показать оба и **дождаться явного согласия**. Это тот самый единственный штамп.
6. **Завершение.** Merge в базовую ветку, тег `change/NNN`, удаление каталога `changes/NNN-*/`.
   Напомнить, как восстановить: `git show change/NNN:specs/changes/NNN-*/verdict.md`.

## Границы

- Не архивировать дельту: каталог удаляется, архив отравляет греп (§2, §8).
- Не создавать ADR-файла и не заводить нового класса артефактов (§8).
- Не проверять предусловия скриптом — читать `criteria.md` и запускать `make check`.
- Не мержить без явного согласия человека, ни при каких обстоятельствах.
- Не резать capability-файл самостоятельно.

## Проверка

- Файл существует, фронтматтер парсится.
- Присутствуют оба diff'а, и оба помечены как обязательные к показу.
- Присутствует ожидание явного согласия человека перед merge.
- Присутствуют обе формы провенанса.
- Присутствует удаление каталога дельты и команда восстановления из тега.
- Грепом: нет `archive`, нет `ADR`, нет имени скрипта, нет автоматического merge.
- Присутствует правило multi-target «предлагает команда, утверждает человек».

## Что скажет warden

- Каталог дельты переехал в `archive/` вместо удаления → ОТКЛОНИТЬ (§2: вторая копия ответа
  «что система делает»).
- Merge без явного согласия, «раз все критерии зелёные» → ОТКЛОНИТЬ: человеческий штамп в этом
  воркфлоу один, и он здесь.
- Инварианты без провенанса → ОТКЛОНИТЬ: без имени теста устаревший инвариант ненаходим.
- Скрипт проверки предусловий → ОТКЛОНИТЬ, бюджет ноль. Это `accept.py` под новым именем.
- Команда сама порезала capability-файл по порогу → ОТКЛОНИТЬ: порог — сигнал человеку, не
  автоматическое действие.
- Появился ADR-файл → ОТКЛОНИТЬ (§8), находка в `FINDINGS.md`.
