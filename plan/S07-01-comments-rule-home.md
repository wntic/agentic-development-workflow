# S07-01 — у правила про комментарии появляется кросс-слойный дом

Тип агента: **`adw-builder`**
Слой: **ядро** (`plugins/adw/skills/python-style/SKILL.md`)
Происхождение: замер главной сессии 2026-08-02 по коду `adw-probe`, подтверждённый человеком.
Основание — красная линия 1, измеренный провал:

```bash
cd ~/Projects/adw-probe && python3 -c "
import pathlib
t=c=0
for p in pathlib.Path('src').rglob('*.py'):
    L=[l for l in p.read_text().splitlines() if l.strip()]
    t+=len(L); c+=sum(1 for l in L if l.lstrip().startswith('#'))
print(c,'/',t)"
# 103 / 808 — 13% непустых строк; у i_short_link_repository.py 16 из 25, то есть 64%
```

Читать сначала:
- `plugins/adw/skills/python-style/SKILL.md` целиком — правишь его `## Hard stops`
- пять существующих формулировок правила, чтобы не изобретать шестую:
  `domain-ports:131`, `domain-model:292`, `domain-service:83`, `application:311`,
  `infra-persistence:515`
- `CLAUDE.md`, раздел «How skills work» — про то, что `python-style` кросс-слойный и `paths` не несёт

## Задача

Правило «комментарий только когда *почему* неочевидно, одна короткая строка» живёт в **пяти скиллах
на артефакты** и отсутствует в `python-style` — единственном кросс-слойном скилле про стиль кода.
Роль, подгрузившая кросс-слойную пару `python-style` + `architecture`, правила не видит вовсе.

Замер выше показывает цену: 13% непустых строк `src/` — комментарии, у порта 64%, у delete-хендлера
три многострочных блока при правиле «одна короткая строка максимум».

## Deliverables

Один файл, одна правка.

`python-style/SKILL.md`, секция `## Hard stops` получает строку про комментарии. Требования к ней:

- **формулировка одна из пяти существующих, а не шестая.** Возьми ту, что точнее прочих — у
  `domain-model:292` она развёрнутее всех и уже содержит запрет на многострочный блок;
- **это `Hard stop`, а не абзац раздела.** Секции `## Typing` и `## Logging` описывают, как писать;
  правило про комментарии — запрет, и его дом среди запретов;
- **прецедент формы уже есть в этом же файле**: запрет `from __future__ import annotations` стоит и в
  `python-style`, и в `infra-persistence:515`. Значит дублирование строки в скиллах на артефакты —
  принятая здесь форма, и снимать её оттуда **не нужно**.

## Границы

- **Только `python-style/SKILL.md`.** Пять скиллов с существующей формулировкой не трогать — ни
  править, ни удалять из них строку.
- **Ни одного нового правила о комментариях.** Переносится существующее, дословно или почти.
- **Секции `## Typing` и `## Logging` не трогать.**
- **Про docstring'и ничего не писать** — это отдельный предмет, у него свои дома в скиллах на
  артефакты, и решения по нему нет.
- **Потолок фронтматтера** `description` + `when_to_use` — 1536 символов; если тронешь фронтматтер
  (а трогать его незачем), посчитай.
- Не чинить найденное по дороге.

## Проверка

```bash
git diff --stat -- plugins/adw/skills/                      # ровно один файл
rtk proxy grep -n -i 'comment' plugins/adw/skills/python-style/SKILL.md    # правило на месте
rtk proxy grep -c '^- ' plugins/adw/skills/python-style/SKILL.md           # на одну строку больше, чем было
rtk proxy grep -rn 'No comments unless\|Default to no comments' plugins/adw/skills/ | wc -l   # было 5, стало 6
rtk proxy find plugins/adw -name '*.py' -o -name '*.sh' -o -name 'hooks.json'   # пусто
```

Плюс чтением: строка стоит среди запретов, а не среди описаний; она не пересказывает соседние
пять, а является их кросс-слойным домом.

- **новых правил нет**, перенесена существующая формулировка;
- **чужие скиллы не тронуты**: пять формулировок на местах;
- **объём**: один файл, одна строка.
