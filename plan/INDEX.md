## Версия плагина — правило движения

Решение человека 2026-08-04. Версия живёт в `plugins/adw/.claude-plugin/plugin.json`, начинается с
**`1.0.0`** (влитие четвёртого захода в `main`) и двигается **по шипящемуся**, а не по проходам:

| | когда | пример |
|---|---|---|
| **мажор** | потребительский проект обязан что-то поменять у себя | смена формы маркера `ac("AC-1")` → слаг была бы мажором |
| **минор** | меняется поведение шипящегося: правило скилла, маршрут роли, шаг команды | S08-01…S08-05 — четыре шипящихся файла |
| **патч** | формулировка без смены действий читателя | — |
| **нет подъёма** | тронута только дев-запись (`plan/`, `WORKFLOW.md`, `research/`) | S08-08 — водораздел реестра |

Правило существует затем, чтобы версия не стала счётчиком нашей активности: проход по `plan/`
потребителю не меняет ничего.

**Когда именно поднимается — решение человека 2026-08-04, и оно правит первую редакцию этого же
правила.** Подъём происходит **при публикации наружу** (пуш `main`), а не в конце каждого прохода.
Причина замерена: обязанность «поднять после прохода» падала на оркестратора, а у него четыре
измеренных экземпляра забывания ровно этого класса за один день (F-113, F-154, F-160, F-163) плюс
девять из семьи F-82. Исполнить её было некому и по другой причине: билдеру Границы задачи запрещают
трогать файлы вне Deliverables, а версия ни в одних Deliverables не стоит. Публикация — событие, где
человек и так в контуре, поэтому забыть её нельзя, не забыв сам пуш.

`adw-warden` при этом на каждом проходе говорит, двинулась ли версия, если дифф трогал
`plugins/adw/**` — это чтение роли, а не механизм. Проверка в `pre-commit` рассматривалась и
отвергнута: у дрейфа версии **ноль** замеренных экземпляров, а красная линия 1 запрещает механизм под
`ПРЕДСТАВИМО`.

**Чего версия не покупает, и это замерено.** При установке из каталога (`source: directory`, как во
всех пробах) платформа пишет в `installed_plugins.json` **SHA коммита**, а не semver, и `plugin update`
показывает SHA. Semver читается только при `source: github` — замерено на `claude-agent-report`
(`"version": "1.1.2"`). То есть до переезда маркетплейса в git версия здесь — документация для людей.

## Протокол цепочки (исполняет главная сессия)

Промпт, которым запускается сессия-оркестратор: [ORCHESTRATE.md](ORCHESTRATE.md). Он несёт только
осанку оркестратора и его собственные соблазны; сам протокол — здесь, и второй его копии нет.

**Сначала — не давать машине уснуть.** В фоне, один раз на всю цепочку:

```bash
caffeinate -dimsu
```

**И до первого файла задачи — решения в реестр.** Диспозиции человека ложатся в `FINDINGS.md`
**раньше**, чем написан первый файл задачи, который на них ссылается. Не «до диспатча» — до
**написания**: задача, ссылающаяся на решение, которого в реестре нет, оставляет исполнителю и
warden'у нечего открыть, кроме самой задачи (F-113, три исполнителя поймали это независимо).

Затем на каждую задачу, по порядку зависимостей:

1. **Диспатч.** Один агент на одну задачу, тип по таблице ниже. В промпте — только путь к файлу
   задачи и требование прочитать всё, что названо в её секции «Читать сначала». Ничего больше:
   задача самодостаточна, а пересказ её в промпте — это второй источник правды.
   **Секция «Проверка» задачи предъявляет свой дифф по своим путям** — `git diff --stat -- <пути>`, —
   а не состояние всего дерева: при параллельных диспатчах без коммита между ними `git status`
   даёт ложный красный на честной работе (F-99, поймано двумя builder'ами независимо).
2. **Warden.** По возвращении builder'а — диспатч `adw-warden` со списком изменённых файлов
   (`git status --short` + `git diff`). Warden read-only, он не чинит, он выносит
   `ПРИНЯТЬ` / `ОТКЛОНИТЬ` со ссылкой на правило.
3. **Проверка.** Главная сессия сама прогоняет секцию «Проверка» файла задачи. Не веря отчёту
   builder'а на слово — это тот же принцип, по которому в самом воркфлоу вердикт выносит не автор.
4. **Ветвление.**
   - Warden `ПРИНЯТЬ` + проверка зелёная → коммит, галочка в таблице выше, следующая задача.
   - Warden `ОТКЛОНИТЬ` → повторный диспатч builder'а с вердиктом warden'а. Три круга на задачу,
     дальше остановка и вопрос человеку.
   - Проверка красная → повторный диспатч с конкретикой провала.
5. **Находки.** Всё, что builder или warden нашли, но что не входит в Deliverables задачи, пишет
   **главная сессия** в `FINDINGS.md`. Не builder — иначе находка превращается в правку.

### Типы агентов

| Тип | Для чего | Инструменты |
|---|---|---|
| `adw-prober` | замерить поведение платформы экспериментом; записывает только замеренное | Read, Write, Bash, Glob, Grep, WebFetch |
| `adw-builder` | написать прозаические артефакты задачи (агенты, команды, шаблоны) | Read, Write, Edit, Bash, Glob, Grep |
| `adw-warden` | сверить результат с красными линиями и §8; **read-only, не чинит** | Read, Bash, Glob, Grep |

Определения — в `.claude/agents/`. Это **project-scoped** агенты: они не под `plugins/adw/`,
значит не шипятся. Каталог создан заново, поэтому **до первого диспатча нужен рестарт сессии** —
watcher платформы покрывает только каталоги, существовавшие на старте сессии. Без рестарта
fallback: диспатч `general-purpose` с инструкцией «прочитай `.claude/agents/<имя>.md` и следуй ему».

## Правила, которые делают этот список ограниченным

   починил. Это не бюрократия: 44 производные задачи выросли именно из «пока я здесь, поправлю и
   вот это».
3. **Этот файл — таблица, а не журнал.** У прошлого захода INDEX разросся до 61 КБ прозы. Здесь
   одна строка на задачу и статус. Рассуждения живут в файле задачи, находки — в `FINDINGS.md`.
