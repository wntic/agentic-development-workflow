# plan/ — статус и протокол

`plan/` — **дев-запись, она не шипится.** Правило поставки по местоположению: файл шипится тогда и
только тогда, когда лежит под `plugins/adw/`. Ноль скриптов под `plugins/adw/` — красная линия 2
(бюджет enforcement = ноль).

Здесь живёт только живое: указатели, активная волна, правило версии и протокол цепочки. Волны
исполненных задач не журналятся — файл задачи и секция волны удаляются её **закрывающим коммитом**
(сообщение начинается `plan: SNN closed`), история — в git. Волны B, R и S04…S14 предшествуют этой
конвенции или закрыты ею; их секции и файлы задач читаются из git-истории этого файла
(`git log --oneline -- plan/INDEX.md`).

## Активная волна

Нет активной волны. Секция волны заводится решением человека — с мотивом, развилками и таблицей
задач — и умирает закрывающим коммитом волны.

## Версия плагина — правило движения

Решение человека 2026-08-04. Версия живёт в `plugins/adw/.claude-plugin/plugin.json`, начинается с
**`1.0.0`** (влитие четвёртого захода в `main`) и двигается **по шипящемуся**, а не по проходам:

| | когда | пример |
|---|---|---|
| **мажор** | потребительский проект обязан что-то поменять у себя | смена формы маркера `ac("AC-1")` → слаг была бы мажором |
| **минор** | меняется поведение шипящегося: правило скилла, маршрут роли, шаг команды | S08-01…S08-05 — четыре шипящихся файла |
| **патч** | формулировка без смены действий читателя | — |
| **нет подъёма** | тронута только дев-запись (`plan/`, `WORKFLOW.md`, `research/`) | S08-08 — водораздел реестра |

Правило существует затем, чтобы версия не стала счётчиком нашей активности: проход по `plan/`
потребителю не меняет ничего.

**Когда именно поднимается — решение человека 2026-08-04, и оно правит первую редакцию этого же
правила.** Подъём происходит **при публикации наружу** (пуш `main`), а не в конце каждого прохода.
Причина замерена: обязанность «поднять после прохода» падала на оркестратора, а у него четыре
измеренных экземпляра забывания ровно этого класса за один день (F-113, F-154, F-160, F-163) плюс
девять из семьи F-82. Исполнить её было некому и по другой причине: билдеру Границы задачи запрещают
трогать файлы вне Deliverables, а версия ни в одних Deliverables не стоит. Публикация — событие, где
человек и так в контуре, поэтому забыть её нельзя, не забыв сам пуш. Подъём **готовится командой
`/ship`**: она собирает шипящийся дифф от последнего движения версии, классифицирует его по таблице
выше и предлагает; решает человек, пуш — по его отдельному слову.

`adw-warden` при этом на каждом проходе говорит, двинулась ли версия, если дифф трогал
`plugins/adw/**` — это чтение роли, а не механизм. Проверка в `pre-commit` рассматривалась и
отвергнута: у дрейфа версии **ноль** замеренных экземпляров, а красная линия 1 запрещает механизм под
`ПРЕДСТАВИМО`.

**Чего версия не покупает, и это замерено.** При установке из каталога (`source: directory`, как во
всех пробах) платформа пишет в `installed_plugins.json` **SHA коммита**, а не semver, и `plugin update`
показывает SHA. Semver читается только при `source: github` — замерено на `claude-agent-report`
(`"version": "1.1.2"`). То есть до переезда маркетплейса в git версия здесь — документация для людей.

## Протокол цепочки (исполняет главная сессия)

Оркестратор — обычная главная сессия: `CLAUDE.md` подхватывается сам, протокол читается здесь.
Отдельного стартового промпта нет — `ORCHESTRATE.md` снят волной S15 (человек им не пользовался ни
разу; F-275 закрыта снятием причины), и второй копии протокола не существует.

**Осанка главной сессии — её собственные соблазны, все измеренные.** «Тут мелочь, поправлю сам» —
нет: правка оркестратора не проходит через warden'а, значит не проходит вообще. «Builder отчитался,
что зелено» — шаг 3 ниже, прогоняй сам. «Warden отклонил, но он не прав» — может быть, и тогда это
вопрос человеку с цитатой, а не решение переступить. «Появилась задача по ходу» — правило 1 внизу
файла. И общий выход: **останов — нормальный исход, догадка вместо вопроса — провал**; спрашивай
человека, когда три круга не закрыли задачу, когда warden и проверка противоречат друг другу, когда
замер противоречит канону (канон правит только человек) и когда задача требует решения, которого нет
ни в ней, ни в каноне. Не пушить без человека: публикация — событие подъёма версии.

**Сначала — не давать машине уснуть.** В фоне, один раз на всю цепочку:

```bash
caffeinate -dimsu
```

**И до первого файла задачи — решения в реестр.** Диспозиции человека ложатся в файл
события-источника под `plan/findings/` (датированной секцией в его конце) **раньше**, чем написан
первый файл задачи, который на них ссылается; решение волны-«хотелки», не привязанной к находкам,
записывается в секцию активной волны этого файла. Не «до диспатча» — до **написания**: задача,
ссылающаяся на решение, которого в реестре нет, оставляет исполнителю и warden'у нечего открыть,
кроме самой задачи (F-113, три исполнителя поймали это независимо).

Затем на каждую задачу, по порядку зависимостей:

1. **Диспатч.** Один агент на одну задачу, тип по таблице ниже. В промпте — только путь к файлу
   задачи и требование прочитать всё, что названо в её секции «Читать сначала». Ничего больше:
   задача самодостаточна, а пересказ её в промпте — это второй источник правды.
   **Секция «Проверка» задачи предъявляет свой дифф по своим путям** — `git diff --stat -- <пути>`, —
   а не состояние всего дерева: при параллельных диспатчах без коммита между ними `git status`
   даёт ложный красный на честной работе (F-99, поймано двумя builder'ами независимо).

   **Команда проверки красной линии 2 копируется в новый файл задачи из карты дословно** — из
   `ORIENT.md` §4, блок под «Написать скрипт», — а не пишется по памяти. Правило лечит причину класса,
   а не свой экземпляр: копия команды расходится с оригиналом **молча**, потому что обе формы дают
   пустой вывод ровно до того дня, когда расхождение начинает что-то значить. Экземпляр — F-132: 22
   исполненных файла задач искали на один предикат меньше, чем карта, и в день, когда этот предикат
   что-нибудь найдёт, все проверки нулевого бюджета отдали бы зелёное. Тот же класс, что F-71 и F-87.
   **Исполненные файлы задач при этом не правятся** — правка задним числом подделала бы протокол
   (ruling F-71); с S14 они и не лежат в дереве — живой адресат правила один: файл задачи, который
   ещё пишется. Второй копии самой команды в этом файле намеренно нет — дом у неё один, и он в карте.
2. **Warden.** По возвращении builder'а — диспатч `adw-warden` со списком изменённых файлов **от
   главной сессии в промпте** (при параллельной волне — с оговоркой, чьи следы в дереве чужие:
   голый `git status` у warden'а — открытая F-276). Warden read-only, он не чинит, он выносит
   `ПРИНЯТЬ` / `ОТКЛОНИТЬ` со ссылкой на правило.
3. **Проверка.** Главная сессия сама прогоняет секцию «Проверка» файла задачи. Не веря отчёту
   builder'а на слово — это тот же принцип, по которому в самом воркфлоу вердикт выносит не автор.
4. **Ветвление.**
   - Warden `ПРИНЯТЬ` + проверка зелёная → коммит, галочка в таблице активной волны, следующая задача.
   - Warden `ОТКЛОНИТЬ` → повторный диспатч builder'а с вердиктом warden'а. Три круга на задачу,
     дальше остановка и вопрос человеку. **Доворот повторного диспатча ограничен вердиктом
     warden'а и ссылкой на строку реестра** — всё остальное пишется в файл задачи, где остаётся
     следом: доворот — канал без следа, и он уже сослался на диспозицию, которой в реестре нет;
     правило «задача самодостаточна» существует именно против него (F-231).
     **При повторном диспатче «до»-состояние «Проверки» переопределяется явно** — состояние на
     момент отклонения, а не нетронутое дерево: после коммита первого круга записанного «до» больше
     нет, а числа «после» сошлись бы и у исполнителя, принявшего чужой коммит за свою работу
     (F-233).
   - Проверка красная → повторный диспатч с конкретикой провала.

   **Коммит ставит свои пути** — `git add <пути задачи>`; `git add <каталог>` и `git add -A` в
   волне запрещены, симметрично правилу шага 1 о том, что проверка предъявляет свой дифф по своим
   путям: `git add plan/` измеренно закоммитил чужую незаревьюенную и одну отклонённую работу —
   ложный зелёный, зеркало ложного красного F-99 (F-230).

   **Главная сессия не коммитит, пока в дереве живёт незакоммиченный дифф диспатчнутой задачи**:
   pre-commit-стэш при живом чужом дифе измеренно снёс неотслеживаемый deliverable (F-281).
5. **Находки.** Всё, что builder или warden нашли, но что не входит в Deliverables задачи, пишет
   **главная сессия** в файл события-источника под `plan/findings/` (формат — `ORIENT` §5). Не
   builder — иначе находка превращается в правку.

   **Задача, которая ставит гейт, показывает его срабатывание.** Коммит, устанавливающий гейт, —
   единственный, где работоспособность гейта ненаблюдаема: если тот же коммит починил всё, что гейт
   ловит, вывод `make check` **побитово одинаков** с гейтом и без него, поэтому зелёный не доказывает
   ничего. Строка, попавшая не в ту таблицу или с опечаткой в ключе, оставляет `make check` зелёным и
   **неотличимым от рабочего гейта** — и следующий случай проезжает мимо, но теперь под уверенностью,
   что защита стоит (F-178; без этого F-170 повторяется в худшей форме). Поэтому отчёт несёт вывод
   **одноразового случая вне дерева проекта** — входа, который гейт обязан поймать. В проекте случай
   не остаётся: это не тест проекта, а доказательство, что строка читается. Приём **изобрёл
   исполнитель** — builder S09-05 заметил ненаблюдаемость сам и прогнал тест-пустышку из каталога вне
   дерева пробы, — а правило его записывает: тот же выбор, что по F-196, и довод у него тот же —
   иначе следующий проход полагается на инициативу исполнителя.
6. **Закрытие волны.** Все задачи приняты и закоммичены → закрывающий коммит: удаляет файлы задач
   волны и её секцию из этого файла, приносит файл(ы) находок волны, если они появились (их судьба
   дальше — модель `findings/`: решены и исполнены → удалены своей волной), и несёт сообщение,
   начинающееся **`plan: SNN closed`**. Счёт проходов читается из git-истории —
   `git log --oneline | grep -c 'plan: S[0-9]* closed'` — плюс волны до конвенции (S04…S13), чьи
   секции лежат в истории этого файла; какие волны идут в счёт красной линии 3, решает человек
   (S11…S14 не идут, решения 2026-08-09).

### Типы агентов

| Тип | Для чего | Инструменты |
|---|---|---|
| `adw-prober` | замерить поведение платформы экспериментом; записывает только замеренное | Read, Write, Bash, Glob, Grep, WebFetch |
| `adw-builder` | написать прозаические артефакты задачи (агенты, команды, шаблоны) | Read, Write, Edit, Bash, Glob, Grep |
| `adw-warden` | сверить результат с красными линиями и §8; **read-only, не чинит** | Read, Bash, Glob, Grep |
| `adw-analyst` | разбор прогона цикла в потребителе по бандлу отчёта; черновики находок текстом | Read, Bash, Glob, Grep |

Определения — в `.claude/agents/`. Это **project-scoped** агенты: они не под `plugins/adw/`, значит
не шипятся. `adw-analyst` диспатчится командой `/debrief`, не цепочкой. Новый файл в существующем
каталоге агентов подхватывается между ходами без рестарта (`PLATFORM.md`); свежесозданный каталог —
нет, для него нужен рестарт сессии.

## Правила, которые делают этот список ограниченным

Прошлый заход декомпозировался в 11 задач и вырос до 64 — 44 производные задачи родились в
процессе. Три правила против этого, и warden проверяет каждое:

1. **Восьмая задача — видимое событие.** Новая задача не добавляется builder'ом и не появляется
   «по ходу». Находка идёт в файл события-источника под `plan/findings/`; превращение находки в
   задачу — решение человека, отдельным коммитом, с ответом на вопрос «какой измеренный провал она
   лечит».
2. **Задача не растёт за свои Deliverables.** Обнаружил рядом проблему — записал в находки, не
   починил. Это не бюрократия: 44 производные задачи выросли именно из «пока я здесь, поправлю и
   вот это».
3. **Этот файл — таблица, а не журнал.** У прошлого захода INDEX разросся до 61 КБ прозы; у этого —
   до 630 строк журнала волн, срезанных S14. Здесь одна строка на задачу и статус, секция волны
   умирает с волной; рассуждения живут в файле задачи, находки — в файлах `plan/findings/`.
