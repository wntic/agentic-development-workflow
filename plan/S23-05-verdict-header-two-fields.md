# S23-05 — шапка вердикта получает два поля: SHA дерева воркфлоу и ответ `alembic check`

Тип агента: **`adw-builder`**
Слой: **шипящееся** (`plugins/adw/templates/verdict.md`) — warden докладывает про версию; подъём
готовит `/ship` при публикации, здесь версия не двигается.
Происхождение: два решения человека 2026-08-10 об одной шапке — **F-265**
(`plan/findings/legacy.md`, секция «Решения человека, 2026-08-10 — девятая чистка (волна S23)») и
**s22-wave-1** (`plan/findings/s22-wave.md`, секция «Решения человека, 2026-08-10 — исполнение
s22-wave-1»). Разведение их по волнам правило бы шапку дважды и дважды двинуло минор.

**Что это за задача.**

Первое поле (F-265): **ни один прогон не приколочен к версии плагина.** Маркетплейс зарегистрирован
с `installLocation` в само рабочее дерево — замерено сентинелом: все три потребителя видят скилл,
положенный в дерево, и не видят после удаления, ни в одном кэше его нет. Правка воркфлоу во время
прогона меняет плагин под ним, и случай не гипотетический: волна S10 за 14 часов правила десять
шипящихся скиллов, обе пробы всё это время читали дерево. Весь дефект-лог атрибутирует находки
прогонам («измерено на change 003»), и атрибуция молча предполагает неподвижный плагин. SHA дерева
воркфлоу в вердикте делает её проверяемой задним числом.

Второе поле (s22-wave-1): решение по F-260 обязало оценщика назвать вывод `alembic check` «in the
verdict», а поля под него в шаблоне нет — шапка несёт три (`Baseline`, `Commit`, `` `make check` ``).
Ответ приземляется только в блок доклада роли, который читает цикл, а не человек на приёмке — ради
которого развилка и выбиралась. Без этого поля решение исполнено наполовину.

Читать сначала:

- `plugins/adw/templates/verdict.md` — шапка и комментарии над ней целиком: комментарий про
  `Baseline` показывает, как этот файл объясняет **зачем** поле, а не только что в него писать;
- `plugins/adw/agents/evaluator.md` — условие, при котором роль гоняет `alembic check`
  (`rtk proxy grep -n 'alembic' plugins/adw/agents/evaluator.md`), и форма её доклада: поле шаблона
  должно быть в той же условности, теми же словами;
- тело F-265 грепом: `rtk proxy grep -n '^## F-265 ' plan/findings/legacy.md`, затем ~28 строк;
  тело s22-wave-1 — `plan/findings/s22-wave.md`, первая запись, файл короткий;
- обе строки решений в датированных секциях в конце обоих файлов.

## Задача

1. Поле под SHA дерева воркфлоу: какой ревизии репозитория воркфлоу принадлежал плагин, под которым
   шёл прогон. Коротким комментарием — **зачем**: плагин читается из рабочего дерева, оно двигалось
   во время прогонов, и без этой строки «измерено на change NNN» непроверяемо.
2. Поле под ответ `alembic check`, **условное**, в той же условности, что в роли: изменение,
   тронувшее и `Table`, и ревизию, несёт вывод; изменение, не тронувшее миграции, — `not applicable`.
3. Оба поля встают **рядом с существующими тремя**, не вместо них; `Baseline`, `Commit` и
   `` `make check` `` и их комментарии не переформулируются.
4. Ничего больше: разделы `## Criteria`, `## Edits to tests/** after baseline`, `## Adversarial pass`
   не трогаются.

Файл шипится — текст английский, в тоне файла; номеров находок в нём нет и не появляется.

## Deliverables

Правка в одном файле `plugins/adw/templates/verdict.md`. Больше ничего.

## Границы

- Другие файлы `plugins/adw/**` (включая `evaluator.md` — он уже исполнен, его правит не эта
  задача), `plan/**` (кроме чтения), `.claude/**` — не трогать.
- `plugin.json` не трогать: версия двигается командой `/ship` при публикации.
- Никакого механизма: два поля формы, которую заполняет роль и читает человек. Ни проверки, что они
  заполнены, ни скрипта, извлекающего SHA.
- Не чинить найденное по дороге: находка — в отчёт.

## Проверка

Прогнана на нетронутом дереве до отправки задачи **записанными строками**; ответ «до» назван у
каждой.

```bash
rtk proxy grep -ci 'alembic' plugins/adw/templates/verdict.md
# до: 0. После: ≥1 — поле под ответ стоит
rtk proxy grep -ci 'workflow tree\|plugin sha' plugins/adw/templates/verdict.md
# до: 0. После: ≥1 — поле под SHA дерева воркфлоу стоит
rtk proxy grep -c 'Baseline:' plugins/adw/templates/verdict.md
# до: 1. После: 1 — существующее поле не задвоено и не переписано
rtk proxy grep -c 'not applicable' plugins/adw/templates/verdict.md
# до: 0. После: ≥1 — условность названа так же, как в роли
git diff --stat -- plugins/adw/templates/verdict.md
# до: пусто. После: один файл
git status --porcelain -- plugins/adw/agents/ plugins/adw/.claude-plugin/
# до: пусто. После: пусто — ни роль, ни версия не тронуты
rtk proxy find plugins/adw -name '*.py' -o -name '*.sh' -o -name 'hooks.json' -o -name 'anchors.json'
# до: пусто. После: пусто — красная линия 2
```

## Что скажет warden

- дифф — один файл `templates/verdict.md`, два поля добавлены рядом с тремя существующими;
- условность поля `alembic check` совпадает с условностью в роли — не шире и не уже;
- у поля SHA сказано **зачем** оно, а не только что писать, — по идиоме комментария `Baseline`;
- три существующих поля и их комментарии не сменили смысл; разделы ниже не тронуты;
- текст английский, номеров находок нет; версия `plugins/adw` не тронута;
- механизма нет: ни проверки заполненности, ни скрипта.
