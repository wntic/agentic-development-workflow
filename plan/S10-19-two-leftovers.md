# S10-19 — два остатка: шаблон вердикта догоняет роль, команда теряет ссылку на §6

Тип агента: **`adw-builder`**
Слой: **ядро** (`plugins/adw/templates/verdict.md`) и **адаптер** (`plugins/adw/commands/build.md`)
Происхождение: решение человека 2026-08-05, `plan/FINDINGS.md`, секция «Решения человека, 2026-08-05 —
принятые в ходе исполнения S10», строки **F-214** и **F-216**.

**Девятнадцатая задача — видимое событие, и она не новый предмет.** Оба остатка — последний файл двух уже
принятых решений: F-196 (adversarial-проход применяется, а не рассуждается) и F-207 (висячие ссылки на
разделы канона уходят из шипящегося). Находки записаны главной сессией, диспозиция принята человеком
отдельным решением и легла в реестр **до** написания этого файла.

Читать сначала:
- в `plan/FINDINGS.md` — тела **F-214** и **F-216** заголовочным грепом
  (`rtk proxy grep '^## F-' plan/FINDINGS.md`, потом читать только эти две записи), и обе строки диспозиции
  в названной секции;
- там же — тела **F-196** и **F-207**: остатки исполняют **их**, и формулировки берутся оттуда;
- `plugins/adw/templates/verdict.md` — раздел `## Adversarial pass` (~35–42) целиком, вместе с его
  HTML-комментарием;
- `plugins/adw/agents/evaluator.md` — раздел `## What you write`, подпункт `The adversarial pass` **после
  правки S10-13** (уже закоммичена): шаблон приводится **к нему**, а не к формулировке из этого файла;
- `plugins/adw/commands/build.md` — строка **280**, «and the design document's own §6 states it the same
  way».

Основание замерено:

```bash
sed -n '35,42p' plugins/adw/templates/verdict.md
# «Take a criterion, name a plausible wrong implementation, and say whether any test would catch it.»
rtk proxy grep -rn '§[0-9]\|WORKFLOW' plugins/adw/
# единственное совпадение по всему шипящемуся: commands/build.md:280
```

Первое — **дословно** та формулировка, которую F-196 замерила как недостаточную. Evaluator пишет именно в
этот шаблон, то есть раздел, который он заполняет, велит рассуждать там, где его роль велит прогонять.
Второе — «design document» и его `§6` в потребительском проекте не существуют.

## Задача

**Часть 1 — шаблон догоняет роль (F-214), файл `templates/verdict.md`.** Комментарий раздела
`## Adversarial pass` перестаёт говорить «name … and **say whether**» и говорит то, что теперь говорит
`evaluator.md`: неверная реализация **применяется**, сюита прогоняется, правка **откатывается**, чистота
дерева подтверждается; там, где мутацию не построить, остаётся названная неверная версия с разбором, и в
вердикте сказано, что из двух сделано.

Требования:

- формулировка **сверяется с ролью** и не изобретается: у роли и шаблона должна быть одна форма, иначе
  задача воспроизводит собственный предмет;
- перечисление слабых утверждений («status checked but body ignored…») **остаётся** — оно верно и не про
  форму прохода;
- шаблон — это то, что читатель копирует: если форма требует числа (что прогон дал), в образце должно быть
  видно, куда оно пишется.

**Часть 2 — команда теряет ссылку на §6 (F-216), файл `build.md`, строка 280.** Оборот «and the design
document's own §6 states it the same way» уходит. Что остаётся: сам факт — потолок считается диспатчами
имплементера, а не полными проходами, — и дата решения. Что уходит: указание сверить это по документу,
которого у читателя нет.

Требования:

- **число потолка и дату 2026-07-29 не трогать** — уходит только ссылка на документ и его раздел;
- замена не должна оказаться другой протечкой: ни `WORKFLOW`, ни `§N`, ни «дизайн-документ» в любой форме;
- после правки свип `rtk proxy grep -rn '§[0-9]\|WORKFLOW' plugins/adw/` обязан быть **пуст**.

## Deliverables

Два файла, две правки. Больше ничего.

## Границы

- **Только эти два файла.** `evaluator.md` уже исправлен задачей S10-13 и **не трогается** — шаблон
  приводится к нему, а не наоборот.
- **Перечисление слабых утверждений в шаблоне не сокращать.**
- **Ни одного нового обязательного раздела в шаблоне** — правится комментарий существующего.
- **Потолок, `41.7 thousand tokens` и дата 2026-07-29 в `build.md` — не трогать.**
- **Пункт про убитый диспатч, добавленный S10-13, не трогать.**
- **Проб не править.**
- Не чинить найденное по дороге — находка идёт в `plan/FINDINGS.md`, и пишет её главная сессия.

## Проверка

Прогнана на нетронутом дереве до отправки задачи; ответ «до» назван у каждой строки.

```bash
git diff --stat -- plugins/adw/templates/verdict.md plugins/adw/commands/build.md
# до: пусто. После: ровно два файла
rtk proxy grep -c 'name a plausible wrong implementation' plugins/adw/templates/verdict.md
# до: 1. После: 0 — форма рассуждения ушла
# (моя первая форма — «say whether any test would catch it» — дала 0 на нетронутом дереве, потому что
#  фраза РАЗОРВАНА переводом строки в файле («…and say» / «whether any test…»), а grep работает по
#  строкам. Прогон до отправки поймал это — правило F-136, десятый раз за проход, и первый на переносе)
rtk proxy grep -c 'revert\|reverted' plugins/adw/templates/verdict.md
# до: 0. После: не ноль — откат назван, то есть форма та же, что у роли
rtk proxy grep -c 'status checked but body ignored' plugins/adw/templates/verdict.md
# до: 1. После: 1 — перечисление слабых утверждений цело
rtk proxy grep -rn '§[0-9]\|WORKFLOW' plugins/adw/
# до: одна строка, commands/build.md:280. После: пусто по всему шипящемуся
rtk proxy grep -c 'The ceiling is two dispatches' plugins/adw/commands/build.md
# до: 1. После: 1
rtk proxy grep -c '2026-07-29' plugins/adw/commands/build.md
# до: 2. После: 2 — дата решения цела
rtk proxy grep -c 'no progress for\|Agent stalled' plugins/adw/commands/build.md
# до: 1. После: 1 — пункт S10-13 не тронут
rtk proxy find plugins/adw -name '*.py' -o -name '*.sh' -o -name 'hooks.json' -o -name 'anchors.json'
# до: пусто. После: пусто — красная линия 2
```

## Что скажет warden

- **два файла**, и `evaluator.md` в диффе **отсутствует** — шаблон приводился к роли, а не наоборот;
- **форма в шаблоне и в роли одна** — это главный пункт: разойдись они, и задача воспроизвела бы F-214;
- **свип по всему `plugins/adw/` пуст** по `§N` и `WORKFLOW` — не по `skills/`, потому что узкий свип и был
  причиной F-216;
- **потолок, дата и пункт про убитый диспатч целы** — предъявляется числами;
- **перечисление слабых утверждений не сокращено**;
- **числа рядом с командами** — каждая строка «Проверки» несёт «до» и «после» (правило раунда 1, F-156).
