# B03 — шаблоны артефактов

Тип агента: **`adw-builder`**
Слой: **ядро** (чистый Markdown, переносится как есть)
Зависит от: —

Читать сначала:
- `WORKFLOW.md` §2 (хранилище), §3 и §3.1 (форматы, глубины, секция `Design`), §7 (`make check`)

## Задача

Скелеты артефактов, которые `/adw:spec` и `/adw:accept` кладут в целевой проект. Шаблон — это
**форма с подсказками**, а не заполненный пример: заполненный пример становится тем, что агент
скопирует вместе с содержимым.

## Deliverables

`plugins/adw/templates/`:

- **`spec.md`** — дельта по §3: `Affects`, `Depth`, `Why` (M/L), `Changes` с `ADDED`/`MODIFIED`/
  `REMOVED` и сценариями `WHEN … THEN`, `Out of scope`, `Design` (**с комментарием, что секция
  появляется только при сработавшем структурном триггере §3.1, и что binding она только в части
  разделяемых имён**), `Verification`.
- **`criteria.md`** — чеклист, три состояния `[ ]` / `[x]` / `[m]` с расшифровкой в комментарии;
  напоминание про маркер `@pytest.mark.ac("AC-n")` и про то, что хотя бы один критиерий обязан
  проверяться через реально поднятое приложение.
- **`verdict.md`** — по критерию: PASS / FAIL / MANUAL, чем доказано, git SHA. Плюс два
  обязательных раздела: правки в `tests/**` после baseline и адверсариальный проход.
- **`capability.md`** — скелет живой спеки: назначение, операции, инварианты **с провенансом**
  (`*(verified by: <test_id>)*` / `*(MANUAL)*`). В комментарии — порог ~300 строк и что за ним
  делать.
- **`Makefile`** — цель `check` по §7, ровно четыре команды, ни одной больше.

## Границы

- Ни одной обязательной секции сверх `Changes`. Обязательные секции — это обязательные поля
  манифеста в новой одежде (§3).
- Никаких `status:` / `owner:` / `priority:` и прочего process state в артефактах.
- Ни одного поля, которое кто-то должен парсить машиной. Читатель — человек и агент.
- Не писать шаблона `overview.md` контекста: одна capability = один файл, пока не измерена нужда
  в карте.
- Не заполнять шаблоны реалистичным контентом предметной области.

## Проверка

- Пять файлов существуют.
- `templates/spec.md`: единственная секция без пометки «опционально / только M-L / только по
  триггеру» — это `Changes`.
- `templates/Makefile`: цель `check` содержит ровно `ruff check`, `ruff format --check`,
  `mypy src tests`, `pytest` — и ничего кроме. Грепом: нет упоминаний junit, xml, coverage.
- `templates/criteria.md`: присутствуют все три состояния и маркер `ac(`.
- `templates/capability.md`: присутствуют обе формы провенанса.
- Грепом по всем пяти: нет `status:`, нет `gate`, нет имени скрипта.

## Что скажет warden

- Обязательная секция сверх `Changes` → ОТКЛОНИТЬ (§3).
- Поле статуса или владельца → ОТКЛОНИТЬ (process state в спеке — наследие манифеста).
- `Makefile` вырос пятой командой (coverage, junit, security-скан) → ОТКЛОНИТЬ (§7: определение
  «зелёного» ровно одно, и оно не растёт «пока мы здесь»).
- Шаблон заполнен правдоподобным примером на всю секцию → ОТКЛОНИТЬ: это станет копипастой.
- Появился шаблон, которого нет в Deliverables → ОТКЛОНИТЬ, находка идёт в `FINDINGS.md`.
