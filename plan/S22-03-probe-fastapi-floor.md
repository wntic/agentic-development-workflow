# S22-03 — замер: пол версии FastAPI для `iter_route_contexts`, и как именно падает прогон

Тип агента: **`adw-prober`**
Слой: **дев-запись** (`plan/PLATFORM.md`)
Происхождение: решение человека 2026-08-10, `plan/findings/legacy.md`, секция «Решения человека,
2026-08-10 — восьмая чистка (волна S22), шаблоны инвариантов», строки **F-249** и **F-261**.

**Что это за задача.** Два шаблона `test-discovery-invariants` импортируют
`from fastapi.routing import APIRoute, RouteContext, iter_route_contexts`. На версии, где этого API
ещё нет, будет `ImportError`. Две записи реестра расходятся **по существу** в оценке последствия:

- F-249: «отказ при этом **громкий**, а не тихий, то есть строго лучше нынешнего зелёного молчания,
  и лечения не просит»;
- F-261: «`ImportError` на **сборе**, то есть весь файл инварианта исчезает из прогона — ровно та
  тишина, против которой в том же диффе написана непустая проверка `assert operations`».

Обе `ПРЕДСТАВИМО` — поведение на старой версии никто не наблюдал. Замер решает спор.

Читать сначала:

- `plan/PLATFORM.md` — форма датированного раздела и легенда классов (`ЗАМЕРЕНО` / `НЕ ПРОВЕРЕНО` —
  законченный ответ);
- тела записей грепом, **не читая `legacy.md` целиком** (`ORIENT.md` §5):
  `rtk proxy grep -n '^## F-249 \|^## F-261 ' plan/findings/legacy.md`, затем ~10 и ~18 строк;
- строки решений по обеим в секции решений 2026-08-10 (восьмая чистка) в конце того же файла;
- `plugins/adw/skills/conventions/SKILL.md`, строки про запрет версий в субстрате и исключение
  «known breaking-version boundary» (`rtk proxy grep -n 'breaking-version boundary' <файл>`) — чтобы
  раздел назвал, годится ли найденный пол под это исключение.

## Задача

1. В одноразовом venv (scratchpad, **не** в дереве репозитория и **не** в пробах) поставить FastAPI
   версиями вниз от 0.140 и найти **первую, где `from fastapi.routing import iter_route_contexts`
   падает**. Назвать обе граничные версии: последнюю рабочую и первую падающую.
2. **Отдельно измерить, как падает прогон**, — это и есть спор F-249 против F-261. Собрать
   минимальный файл теста, импортирующий шаблонную форму, и прогнать `pytest` на падающей версии:
   что печатается, каков код возврата, исчезает ли файл из прогона молча или прогон краснеет. Если
   поведение зависит от флагов (`--continue-on-collection-errors` и подобных) — назвать это.
3. Записать в `plan/PLATFORM.md` датированный раздел по форме файла: команда, вывод, вывод из
   вывода. Раздел **называет своим текстом**, какая из двух записей подтвердилась, — не ссылаясь на
   их номера (это дев-запись реестра, а `PLATFORM.md` — про платформу и субстрат); достаточно
   сказать, громкий отказ или тихий, и чем это показано.
4. Версию платформы и версии FastAPI — в раздел. Прошлые датированные разделы не править.
