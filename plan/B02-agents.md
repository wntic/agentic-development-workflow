# B02 — четыре агента цикла

Тип агента: **`adw-builder`**
Слой: тела промптов — **ядро** (переносимы), фронтматтер — **адаптер**
Зависит от: B01

Читать сначала:
- `WORKFLOW.md` §5 (таблица ролей), §6 (шаги цикла), §3 (форматы артефактов), §7 (`make check`)
- `plan/PLATFORM.md` — результат B01. **Фронтматтер пишется по нему, не по памяти.**
- `plugins/adw/skills/CONVENTIONS.md` — как устроен каталог знаний, какие темы существуют

## Задача

Четыре определения ролей цикла. Каждое — файл с фронтматтером (адаптер) и прозаическим телом
(ядро). Тело обязано быть понятно агенту в Codex без фронтматтера: это тест переносимости §1.

## Deliverables

`plugins/adw/agents/` — четыре файла:

- **`test-author.md`** — пишет тесты из `spec.md` + `criteria.md`, каждому AC маркер
  `@pytest.mark.ac("AC-n")`. Объявляет зависимости изменения в отдельном коммите **до** baseline.
  Не пишет `src/**`. На первом изменении проекта дополнительно кладёт пакетный корень
  (`conventions`, блок D — форма вызова `uv init --package` там замерена, повторять её в промпте
  нельзя, надо ссылаться).
- **`test-review.md`** — свежий контекст, ничего не пишет. Четыре вопроса из §5: запускаются ли
  тесты; падают ли по правильной причине; есть ли тест на каждый AC; упал бы тест, будь реализация
  неверна вот так и так. Возврат — вердикт с конкретикой, не «выглядит хорошо». Отдельно: подтвердить,
  что pre-baseline diff содержит только `tests/**` и `pyproject.toml`.
- **`implementer.md`** — код до зелёного `make check`. Не правит `tests/**`. Контракт из секции
  `Design` не сошёлся → **CONTRACT-CHANGE в отчёт и остановка**, не молчаливый обход
  default-аргументом. Владеет Alembic-ревизией.
- **`evaluator.md`** — свежий контекст. `make check`; живой прогон тех критериев, окружение под
  которые обеспечила секция `Verification`; флипы `[ ]`↔`[x]` **в обе стороны**; `verdict.md`
  по формату §3. Обязательные разделы вердикта: правки в `tests/**` после baseline и
  адверсариальный проход по силе тестов. Секцию `Design` в её non-binding части игнорирует.

Каждый файл несёт:
- `name`, `description` (когда диспатчить), `tools` по таблице §5, `model: inherit`, `skills` в
  форме, подтверждённой B01;
- **`maxTurns` не ставится.** Решение человека 2026-07-29 по находке F-02 (`FINDINGS.md`): поле
  убрано из фронтматтера, потолок итераций держит диспатчащая сессия счётчиком повторных диспатчей
  и эскалирует человеку. Причина — измеренная молчаливая обрезка со словом `completed`; заодно
  механизм переезжает из адаптера в ядро. Число проходов живёт в `/adw:build` (B05), не здесь;
- в теле — **что роль не может и чем это ловится** (§5: post-hoc diff, не запрет);
- в теле — как выглядит её возврат: конкретный формат отчёта родителю.

## Границы

- Ни `permissionMode`, ни `hooks`, ни `mcpServers`: плагинные агенты их игнорируют.
- Ни одного `disallowedTools` с путём или глобом — платформой не выражается.
- Не писать команд `/adw:*`. Это B04–B06.
- Не писать шаблонов артефактов. Это B03.
- Не заводить пятую роль. Ролей четыре, §5.

## Проверка

- Четыре файла существуют, фронтматтер парсится (`python3 -c` с ручным разбором либо
  `head -20` + глазами — но не новый скрипт в репозитории).
- Каждое поле фронтматтера, касающееся платформы, имеет подтверждение в `plan/PLATFORM.md`.
- Ни в одном файле нет: `permissionMode`, `hooks:`, `mcpServers`, `disallowedTools` с `/` или `*`,
  `maxTurns`.
- Грепом: ни один файл не упоминает `gate.py`, `accept.py`, `check.py`, хук, хеш, проверку
  целостности.
- Тест переносимости: тело каждого файла читается как инструкция, не ссылающаяся на фронтматтер.
- `test-review.md` и `evaluator.md` содержат слово «свежий контекст» и объясняют, почему это важно.
