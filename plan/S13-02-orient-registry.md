# S13-02 — `ORIENT`: дом формата находки, смерть счётной команды

Тип агента: **`adw-builder`**
Слой: **дев-запись**
Происхождение: решение человека 2026-08-09, `plan/FINDINGS.md`, секция «Решения человека, 2026-08-09 —
реестр по источникам, снос HISTORY.md», буллеты «Формат и правила переезжают в `ORIENT` §5»,
«"Что открыто" = `ls`», «Нумерация».

**Что это за задача.** `plan/ORIENT.md` — карта репозитория; после миграции реестра она врёт в трёх
местах: §5 учит читать файл, которого нет, и несёт счётную команду, которой нечего считать; §4
ссылается на реестр как на дом находок; упоминание `HISTORY.md` в §5 (блок «Архивы прошлых заходов»)
станет висячим после S13-03. Задача правит **один файл** — `plan/ORIENT.md`.

Читать сначала:

- секция решений, названная выше, — целиком;
- `plan/ORIENT.md` §4 и §5 — что именно устаревает;
- шапка `plan/FINDINGS.md` — какие правила из неё **переживают** переезд (формат записи, классы,
  «пишет главная сессия», «число без команды не пишется») и какие умирают (водораздел, форма
  диспозиции с нулевой колонки, счётная команда).

## Задача

Все правки — в `plan/ORIENT.md`.

**1. §5, блок про реестр, переписывается под новую модель.** Он становится домом формата — компактно:

- находки живут в `plan/findings/`, файл на событие-источник (`rooms-004.md`, `s11-audit.md`);
  legacy-очередь замороженной F-серии — `plan/findings/legacy.md`;
- **«что открыто» = `ls plan/findings/`** — пусто significa хорошо; счётная команда, водораздел и
  форма диспозиции умирают вместе с журналом (одной фразой: почему — файл больше не журнал);
- формат записи: `## <имя-файла-без-расширения>-N · <заголовок>`, поля Найдено / Класс /
  Что сломается; классы `ИЗМЕРЕНО` (наблюдение с командой и выводом) / `ПРЕДСТАВИМО` — второе не
  даёт права на механизм; пишет **главная сессия**, не нашедший;
- диспозиции — датированной секцией в конце того же файла; **файл удаляется закрывающим коммитом
  волны**, исполнившей все его решения; история — в git;
- серия F заморожена на F-284; старое тело достаётся `git log -S 'F-NNN' --oneline` и
  `git show <sha>:plan/FINDINGS.md`.

**2. §4 — таблица проверок и прочие упоминания `FINDINGS.md`** правятся указателем: «находка идёт в
файл источника в `plan/findings/`» вместо «в `plan/FINDINGS.md`»; строка про ссылку на решение —
«найди строку в файле источника; нет строки — сначала запиши решение» (смысл не меняется, меняется
адрес). Греп по своим упоминаниям: `rtk proxy grep -n 'FINDINGS' plan/ORIENT.md` — и приведи каждое.

**3. Блок «Архивы прошлых заходов» в §5**: указатель `HISTORY.md` заменяется на `CLAUDE.md` (блок
истории попыток переезжает туда задачей S13-03 этой же волны).

## Deliverables

Один файл `plan/ORIENT.md`. Больше ничего.

## Границы

- `plan/findings/` не трогать — файлы там кладёт S13-01; не жди её возврата, вы в одной волне и
  файлами не пересекаетесь.
- `plan/INDEX.md` не трогать — его правит главная сессия (правило S08).
- Правила, чей дом не §5 (например, «число без команды» из §4), не переезжают и не дублируются —
  правится только адресация реестра.
- Не чинить найденное по дороге: находка — в отчёт.

## Проверка

Прогнана на нетронутом дереве до отправки задачи; ответ «до» назван у каждой строки.

```bash
rtk proxy grep -c 'FINDINGS\.md' plan/ORIENT.md
# до: 12 (пересчитай при исполнении). После: единицы, и каждое оставшееся — про git-историю
# (git show …:plan/FINDINGS.md) или про legacy; живых указателей «пиши в FINDINGS.md» ноль
rtk proxy grep -c 'grep -vxFf' plan/ORIENT.md
# до: 1. После: 0 — счётная команда умерла
rtk proxy grep -c 'ls plan/findings' plan/ORIENT.md
# до: 0. После: ≥1 — новая форма «что открыто» на месте
rtk proxy grep -c 'HISTORY\.md' plan/ORIENT.md
# до: 1. После: 0
git status --porcelain -- plan/ORIENT.md
# до: пусто. После: одна строка M plan/ORIENT.md; больше эта задача не трогает ничего
```

## Что скажет warden

- §5 несёт полный дом формата (запись, классы, кто пишет, правило удаления) — и не несёт трупов:
  ни водораздела, ни счётной команды, ни формы диспозиции с нулевой колонки;
- каждое оставшееся упоминание `FINDINGS.md` — про git-историю или legacy, живых адресов записи нет;
- правки — адресация, не пересмотр правил: «число без команды», «не чинить по дороге» и прочее §4
  не переформулированы;
- один файл в диффе задачи.
