# S18-02 — почему проектов в команде счёта два, и пересчёт числа рядом

Тип агента: **`adw-builder`**
Слой: **дев-запись** (`CLAUDE.md` лежит в корне, не под `plugins/adw/` — не шипится)
Происхождение: решение человека 2026-08-09, `plan/findings/legacy.md`, секция «Решения человека,
2026-08-09 — четвёртая чистка (волна S18), класс „команда врёт правдоподобно“», строка **F-273**.

**Что это за задача.** Команда счёта фич в `CLAUDE.md` перечисляет два репозитория, а тег
`change/NNN` лежит и в третьем проекте — разовом гринфилде, который человек прогнал ради фидбэка и
продолжать не будет. Решение: это **не потребитель**, его изменение в счёт красной линии 3 не идёт, и
команда верна как написана. Не хватает одного предложения о том, **почему** проектов два: без него
следующая сессия натыкается на третий тег и тратит время на разбор — экземпляр уже был, 2026-08-09,
главная сессия при подготовке волны S17.

Заодно пересчитывается число в том же блоке: оно устарело от чужой правки — у `adw-rooms` появился
`change/003`.

Читать сначала:

- `CLAUDE.md`, раздел «Commands», абзац про цикл и блок кода с двумя `git tag` — читать от слов
  «The cycle has now been run against» до конца абзаца после блока;
- тело записи грепом по заголовку, **не читая `legacy.md` целиком** (`ORIENT.md` §5):
  `rtk proxy grep -n '^## F-273 ' plan/findings/legacy.md`, затем ~14 строк;
- строку решения по F-273 в секции решений в конце того же файла — там дословная формулировка
  человека и итоговый счёт;
- `plan/ORIENT.md` §4, строка таблицы про **число**: «посчитай в дереве — и пересчитай **последним
  действием правки**, а не первым».

## Задача

1. Одно предложение о том, почему проектов два: это пробы воркфлоу, которые ведутся дальше, и счёт
   красной линии 3 идёт по ним; **разовый гринфилд, прогнанный ради фидбэка и не имеющий
   продолжения, потребителем не считается и в счёт не входит** (решение человека 2026-08-09).
   **Проект по имени не называть** — он не часть записи о воркфлоу, и канону его имя не нужно.
2. Пересчитать число принятых изменений в том же абзаце — `**eight**` в предложении «The cycle has
   now been run against **eight** accepted changes across two probes». Считать командами из того же
   блока, а не по памяти. **Другие три вхождения слова `eight` в `CLAUDE.md` не трогать** — они про
   другое (записи шага 4 и восемь шагов `/adw:build`).
3. Хвостовые комментарии в блоке кода (`# change/001…006`, `# change/001…002`) **теряют диапазон**:
   они стареют молча и ровно тем же способом, что число, ради которого блок и написан. Остаётся форма
   тега, а не перечень — читателю нужен вид `change/NNN`, а не его границы.

Текст английский: `CLAUDE.md` целиком английский, это не переводится.

## Deliverables

Правка в одном файле `CLAUDE.md`. Больше ничего.

## Границы

- `plan/**`, `plugins/**`, `.claude/**`, `WORKFLOW.md` — не трогать.
- Имя третьего проекта в `CLAUDE.md` не появляется.
- Никакого механизма: ни скрипта счёта, ни проверки, ни хука. Предложение — проза.
- Абзац не переписывается шире названного: предложение про «count them rather than trusting this
  line» и ссылка на F-258 остаются на месте.
- Не чинить найденное по дороге: находка — в отчёт.

## Проверка

Прогнана на нетронутом дереве до отправки задачи; ответ «до» назван у каждой строки.

```bash
rtk proxy grep -c 'adw-probe && git tag' CLAUDE.md
# до: 1. После: 1 — команда на месте, перечисление не расширено
rtk proxy grep -ci 'crawler' CLAUDE.md
# до: 0. После: 0 — имя третьего проекта в каноне не появилось
rtk proxy grep -c 'change/001…002' CLAUDE.md
# до: 1. После: 0 — стареющий диапазон в комментарии снят
rtk proxy grep -c 'eight' CLAUDE.md
# до: 4. После: 3 — пересчитано ровно одно вхождение, три соседних не тронуты
rtk proxy grep -c 'F-258' CLAUDE.md
# до: 1. После: ≥1 — ссылка на причину, по которой блок вообще написан, цела
git diff --stat -- CLAUDE.md
# до: пусто. После: один файл — вклад задачи только здесь
rtk proxy find plugins/adw -name '*.py' -o -name '*.sh' -o -name 'hooks.json' -o -name 'anchors.json'
# до: пусто. После: пусто — красная линия 2
```

Число, поставленное вместо `**eight**`, проверяется тем же способом, каким получено:

```bash
cd ~/Projects/adw-probe && git tag | wc -l ; cd ~/Projects/adw-rooms && git tag | wc -l
# сумма двух чисел — то, что должно стоять в тексте
```

## Что скажет warden

- дифф — один файл `CLAUDE.md`: одно добавленное предложение, одно пересчитанное число, снятые
  диапазоны в двух комментариях;
- имени третьего проекта в диффе нет;
- число в тексте равно сумме двух `git tag | wc -l` — пересчитано, а не переписано по памяти;
- три соседних вхождения `eight` не тронуты;
- механизма нет: ни скрипта, ни проверки, ни изменения команд.
