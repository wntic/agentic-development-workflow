ПОВОД. Наблюдение: restapi-скиллы местами описывают не конвенции, а целиком куски
кода, лифтнутые из ОДНОГО исходного приложения, которые имплементер копирует вслепую
(прецедент: вшитая MaxRequestSizeMiddleware в restapi-app-bootstrap до появления
restapi-middleware → имплементер копировал её всем подряд). Вопрос: сколько ещё таких.

МЕТОД. Multi-agent workflow (skill-altitude-audit, run wf_8a0b9dd0-0d3): по агенту на
каждый из 47 скиллов судит против 4-пунктовой рубрики → состязательная верификация
findings по каждому скиллу (отсеять плейсхолдеры/намеренные литералы, default-refute при
сомнении) → сборка. 66 агентов, ~3.0M токенов.

РУБРИКА (4 запаха):
  1. app_specific_literal     — конкретное значение исходного приложения вшито как канон
                                (URL/порт, title, realm, имя заголовка, magic-строка),
                                которое должно дериваться/конфигурироваться/отсутствовать.
  2. optional_as_mandatory    — код, корректный лишь при наличии фичи X (auth, downloads,
                                реляционный engine, конкретный middleware/стор), подан как
                                обязательный без сигнала условности.
  3. wrong_altitude           — тело конкретного экземпляра там, где должно быть правило +
                                параметризованная форма («куски кода, не конвенция»).
  4. cross_feature_coupling   — фундаментный/bootstrap-скилл презюмирует наличие ДРУГОЙ фичи.

НЕ дефект (отсеяно верификацией): плейсхолдеры Foo/Bar/myapp/<root>; намеренные literal
full-file Template'ы (meta-skill-author rule 3) если их КОНТЕНТ универсален; универсальные
конвенции/типизация/импорты.

РЕЗУЛЬТАТ. 47 проверено · 48 поднято · 38 ПОДТВЕРЖДЕНО (10 отсеяно) · в 16 скиллах.
  По запахам: optional_as_mandatory 19 · app_specific_literal 11 · cross_feature_coupling 8.
  ~13 high-severity.

ПЕРВОПРИЧИНА (единая). Корпус выдаёт набор фич ОДНОГО исходного приложения как
универсальный: JWT-auth, multi-tenant org-claims, реляционный Postgres-стор, file/xlsx-
загрузки, React-фронт на localhost:3000, 10 MiB size-cap. Манифест давно умеет объявлять
эти фичи условно (auth — manifest-declared; сторы — polyglot; middleware — per-app), но
скиллы отстали: показывают фичу обязательной, без сигнала условности. Дефекты
сконцентрированы в слоях entrypoint / composition / integration-tests — там, где живёт
app-wiring. Чистые 31 — домен, application-query, infra-репозитории, general-*/meta-*,
большинство domain-тестов (нет wiring → нет гнили).

ФИЛОСОФИЯ ПОЧИНКИ. Скиллам не хватает ФИЧЕ-УСЛОВНЫХ вариантов шаблона: «универсальное
ядро + блок, появляющийся только когда манифест объявил фичу». Идиома в каталоге УЖЕ есть —
conventions block C/D гейтит реляционный bootstrap («added only when a uses_bootstrap store
backs a repo»). Распространить тот же приём на auth / CORS / download / middleware. Это НЕ
ослабление literal-шаблонов (они by-design) — это проставление сигналов условности +
параметризация лифтнутых литералов.

ТЕМА 1 — AUTH ПРЕЗЮМИРУЕТСЯ УНИВЕРСАЛЬНЫМ  (~17 findings, 12 скиллов) — ДОМИНИРУЕТ
═══════════════════════════════════════════════════════════════════════════════
Auth — manifest-declared (CLAUDE.md), у vector_rag его нет вовсе (все эндпоинты anonymous).
Любой из перечисленных кусков, скопированный в auth-free приложение → ImportError / dead
поле / ValueError / advertised код, который никто не производит.

T1.1 restapi-app-bootstrap · cross_feature_coupling · HIGH
  Весь dependencies.py презюмирует JWT: импортит CurrentUser/Role из domain.auth,
  container.jwt_verifier(), определяет get_current_user/require_role. Без auth — нет
  domain/auth, нет провайдера, ImportError на старте.
  FIX: dependencies.py условен по наличию auth — либо производится только когда манифест
  несёт auth/верификатор токенов, либо bootstrap эмитит его пустым и auth-скилл дополняет.

T1.2 restapi-app-bootstrap · optional_as_mandatory · MEDIUM
  error_handler.py: ветка `if isinstance(exc, UnauthorizedError): WWW-Authenticate`.
  UnauthorizedError — manifest-declared exception; без auth класса нет → импорт падает.
  (realm="myapp" — это интенд-плейсхолдер, НЕ дефект; дефект — безусловный auth-coupling.)
  FIX: гейтить импорт+ветку на наличие auth; иначе translator — голый DomainError-handler.

T1.3 restapi-endpoint · optional_as_mandatory · HIGH
  Каждый шаблон несёт auth-dependency (`_: CurrentUser = Depends(get_current_user)` /
  `require_role(...)`) + импорты domain.auth и ..dependencies, безусловно. Auth-скилл сам
  имеет строку «Public → none». Без auth — неоткуда импортить, dead code.
  FIX: гейтить auth-dependency по auth_mode маршрута; показать unauthenticated-вариант
  шаблона (без auth-dep, без импортов, без 401); ссылаться на restapi-auth-dependency.

T1.4 restapi-endpoint · optional_as_mandatory · MEDIUM
  `responses=error_responses(401[,403]...)` вшиты в каждый декоратор. 401 — только для
  authenticated, 403 — только для role-gated. На auth-free приложении advertise кодов,
  которые route не может произвести (+ discovery-тесты это ловят).
  FIX: привязать 401/403 к auth_mode маршрута; коды дерайвятся из выбранной auth-dependency.

T1.5 application-command · optional_as_mandatory · HIGH
  Rule 2: «caller_id: UUID — первое поле. Every command carries the actor» + caller_id в
  Template. Поля command-DTO = манифестный `input`; у vector_rag команд (IngestText/
  DeleteDocument) caller_id НЕТ. Без auth — обязательное поле без источника.
  FIX: гейтить actor-поле на наличие authenticated-caller; auth-free приложения опускают.

T1.6 application-command · optional_as_mandatory · MEDIUM (наследник T1.5)

  FIX: универсальная часть — «логируй id затронутого ресурса»; actor-kwarg добавляется

T1.7 restapi-error-responses · optional_as_mandatory · MEDIUM
