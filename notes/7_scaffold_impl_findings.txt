S1 [ВЫСОКО] — `# noqa: F401` слепит верификатор. (+ поглощает S2)
  Симптом. Скаффолдер ставит `# noqa: F401` на каждый «контрактный импорт», чтобы
    красный скаффолд (тела = NotImplementedError → импорты не использованы) прошёл ruff.
    После имплементации это даёт дыру ровно в §0-P3 «детерминизм в верификаторе»:
    (a) импорты САМОГО реализуемого протокола (IUserRepository / ITicketRepository /
        ICanManageTokens) реально НЕ используются (structural typing Python их не требует)
        → noqa прячет мёртвый код НАВСЕГДА;
    (b) большинство остальных noqa-импортов СТАЛИ использоваться после заполнения тела →
        noqa устарел и маскирует любой будущий F401 на этих строках.
  Доказательство. grep: IUserRepository / ITicketRepository / ICanManageTokens встречаются
    в своих файлах ровно 1 раз = только строка импорта. `ruff All checks passed` —
    отчасти артефакт подавления.

  КОРЕНЬ — глубже, чем «агент сымпровизировал». Три слоя:
    (1) `noqa`/`F401` НЕ упоминается нигде в .claude/ → инлайновый noqa агент дописывает сам.
    (2) Промпт скаффолдера УЖЕ содержит правильное правило (scaffolder.md строки 56, 175):
        «emit only the contract-type imports the SIGNATURE names; incidental body imports
        are the implementer's». По нему протокол/исключения/таблица сигнатурой не названы →
        импортирует имплементер по мере использования → F401 не возникает, noqa не нужен.
    (3) НО Template скилла infra-sqlalchemy-repository сам НЕ чист по тулчейну, и скаффолдер
        берёт из него «форму»:
          - строка 46 + правило 232: импортирует IFooRepository, а класс (стр. 75) —
            `class FooRepository:` без наследования → мёртвый импорт В САМОМ ЭТАЛОНЕ (= S2);
          - `_FK_FIELD_MAP` как дефолтная заготовка (стр. 52) → см. I3/I4;
          - `func` импортируется дважды (стр. 38 и 41) → см. I4;
          - `_row_to_entity(self, row: object)` + `row.id` (стр. 79-80) НЕ проходит mypy →
            навязывает downstream `# type: ignore[attr-defined]` → см. I4;
          - импортирует больше исключений, чем нужно конкретному репо → лишние F401.
        Агенты заклеивают грязь Template'а через noqa + type: ignore.

  РЕШЕНИЕ (согласовано 2026-06-08):
    Развилка «протокол в адаптере» → ВЫБРАН R1 (structural / duck typing): от протокола
    НЕ наследуемся, импорт протокола из адаптера УБИРАЕМ. Соответствие mypy проверяет в
    точке использования (DI/хендлер). (R2 — `class X(IProto)` — отклонён: дактайпинг.)
    Чистка Template'ов скиллов — В СКОУПЕ S1 (это корень).

  ПЛАН ФИКСА (3 слоя):
    1. Скиллы (корень) — почистить Template'ы infra-sqlalchemy-repository + infra-capability-
       adapter, чтобы эталон был ЧИСТ по тулчейну как есть:
         - убрать импорт протокола (R1: не импортируем, класс без базы);
         - убрать дефолтный `_FK_FIELD_MAP` (показывать только в варианте «есть FK»);
         - дедуп `func` (один импорт);
         - заменить `row: object` на типобезопасный row→entity паттерн (без type: ignore);
         - в импортах исключений — показать «бери только используемые».
    2. Скаффолдер (scaffolder.md) — явный запрет: «никогда не глушить F401 через noqa;
       неиспользуемый импорт в скаффолде = ты переимпортировал → удали его». Усилить, что
       правило строк 56/175 («только сигнатурные импорты») бьёт грязный Template.
    3. Детерминированная страховка в /verify + self-verify скаффолдера: grep-гейт
       «инлайновый `# noqa: F401` запрещён» (нигде не предписан → наличие = дефект).

       NB: per-file F403/F405 ignore для __init__.py (pyproject) — легитимен, его не трогаем;
       целимся именно в ИНЛАЙНОВЫЙ noqa: F401.

S4 [НИЗКО] — кривой относительный импорт (одиночный случай).
  Симптом. engine.py: `from ..postgres.db_settings import DbSettings` изнутри пакета
    postgres — `..postgres.X` уходит вверх в infrastructure и возвращается в тот же пакет.
    Должно быть `.db_settings` (минимум точек / same-package collapse).
  ПРОВЕРЕНО: это ЕДИНИЧНЫЙ случай, не паттерн. Остальные `from ..` в дереве легитимны —
    `..schemas.errors` (middleware→schemas), `..tables.X` (repositories→tables) — это
    соседние субпакеты (`..sibling.X`, конвенция их разрешает, general-imports-conventions
    стр. 26). Кривой только engine→db_settings, где потребитель и цель в ОДНОМ пакете.
  КОРЕНЬ. Деривация скаффолдера для ребра engine→settings посчитала путь как `..{tech}.{mod}`
    (tech=postgres), не распознав, что потребитель (engine) сам лежит в `{tech}` → правило
    не свернулось в `.mod`.
  НЮАНС §0-P3. Тулчейн это НЕ ловит: импорт резолвится, mypy/ruff молчат (стандартного
    ruff-правила «меньше точек» нет; TID252 про другое). Конвенцию same-package держит только
    корректность скаффолдера, не верификатор — честный прокол «не всё тулчейн-энфорсибельно».
  РЕШЕНИЕ (согласовано 2026-06-08).
    1. scaffolder.md — в деривации импортов явно: цель в ТОМ ЖЕ пакете, что потребитель →
       один дот (`.module`), никогда `..self.X`.
    2. general-imports-conventions — добавить ОБОБЩЁННЫЙ анти-пример (без привязки к postgres):
       «из `pkg/a.py` импорт `pkg/b.py` — это `.b`, НЕ `..pkg.b`». Сейчас правило позитивное,
       анти-кейс не показан.
  СТАТУС: РЕШЕНО; ждёт имплементации.

I2 [СРЕДНЕ] — несанкционированный try/except в application → КОРЕНЬ в МАНИФЕСТЕ.
  Симптом. login_handler.py оборачивает get_by_email в try/except NotFoundError →
    UnauthorizedError. application-query правило 6 (стр. 156): «No try/except, exceptions
    propagate to the central error handler» (безусловно для запросов) → однозначное нарушение.

  ПЕРЕОСМЫСЛЕНИЕ. Это дефект МАНИФЕСТА (архитектор), не самодеятельность имплементера. Цепочка:
    - манифест: IUserRepository.get_by_email(email) -> User, raises [NotFoundError] (бросающий);
    - контракт Login: «нет юзера → UnauthorizedError» — «не найдено» здесь НЕ-ошибочный исход
      (security: не палим существование email);
    - конфликт «протокол бросает NotFoundError vs запрос хочет UnauthorizedError» зажал
      имплементера → вынудил поймать NotFoundError = тот самый запрещённый try/except.
    По конвенции domain-repository-protocol (стр. 52-53): get_by_id бросает NotFoundError, но
    get_by_<other> ВОЛЕН вернуть `Foo | None`, когда not-found не-ошибочен (пример стр. 38:
    `get_by_name -> Foo | None`). Манифест смоделировал метод ВОПРЕКИ house-style.

  РЕШЕНИЕ (согласовано 2026-06-08) — O2: поправить МАНИФЕСТ.
    get_by_email(self, email: Email) -> User | None (убрать NotFoundError у этого метода; в
    эпике он только в Login). Тогда хендлер чист, без try/except:
        user = await self._repo.get_by_email(query.email)
        if user is None: raise UnauthorizedError("Invalid credentials")
        if user.is_blocked: raise ForbiddenError(...)
        ...
    Фейк + реальный репо возвращают None для not-found. Правило «единственный try/except —
    компенсирующая транзакция» НЕ трогаем; house-style подтверждён, не расширен.
    (O1 «санкционировать translation try/except» — ОТКЛОНЁН: разъедает чистое правило ради
    случая, который конвенция уже решает через Optional.)

  ПЛАН ФИКСА.
    1. examples/helpdesk_manifest.yaml — get_by_email → `User | None`, снять NotFoundError у метода.
    2. (вытекает) фейк IUserRepository + реальный user_repository: not-found → return None.
    3. login_handler — переписать на if user is None (это уже сделает имплементер по новому контракту).
  СТАТУС: РЕШЕНО (O2, манифест-фикс); ждёт имплементации.
