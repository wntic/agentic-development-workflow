notes/12 — cross-epic / multi-context scaffolding — BUILT + PROVEN (model A)
===========================================================================
Date: 2026-06-14. Branch: workflow-without-generator. Follows notes/11 (which flagged this as the
unbuilt frontier blocking multi-context apps).

DECISION: model A — monolith, bounded contexts as sibling SUBPACKAGES of one package, shared
substrate. (Model B — separate packages / per-context deployables — deferred to §15.) The user
picked A.

WHAT WAS BUILT
--------------
1. Validator (code) — `validate_manifest.py` resolves cross-epic refs instead of warn-and-skip:
   - `build_cross_index(siblings)` maps (subdomain, category) -> node names from sibling manifests
     (domain nodes carry `subdomain`; exceptions/settings/datastores/handlers/schemas keyed under "*").
   - `check_ref` gained a `category` arg: a `<subdomain>:<Name>` ref RESOLVES if a sibling declares it,
     else it is a real error (`unresolved_cross_epic_ref`). With NO siblings → the legacy non-blocking
     `cross_epic_edge` warning (back-compat single-manifest mode).
   - `validate(... siblings=)` / `validate_file(... sibling_paths=)` / CLI `--app <dir>` (globs
     `<dir>/*/manifest.yaml`, excludes the target). +3 tests (resolve / missing-node-error /
     wrong-subdomain-error); suite 42 green.
2. Knowledge (docs — the scaffolder is an AGENT, so the frontier is mostly knowledge, not code):
   - `conventions` block F "Multi-context apps": a cross-epic ref `<subdomain>:<Name>` is just a
     cross-subdomain reference (strip prefix, import `<Name>` from the `<subdomain>` subpackage); the
     substrate (exceptions.py, Postgres bootstrap + DbSettings, main.py, error_handler.py,
     dependencies.py, containers.py, pyproject.toml) is emitted ONCE from the UNION of contexts, dedup
     by identifier; a same-name-different-shape conflict is surfaced, not merged.
   - `scaffolder.md`: app-mode input (a set of context manifests → one package), bootstrap-inventory +
     brownfield rule made union-aware (regenerate shared files from auth ∪ tickets, never one context
     alone).
   - `/scaffold`: app-mode arg + `--app` pre-flight validation.

THE PROOF (end-to-end multi-context)
------------------------------------
Authored the Tickets manifest (epic 02, subdomain tickets) as the architect: TicketStatus (free enum,
OPEN only — the parked status-model question resolved to a free StrEnum, no guarded table),
Title/Description VOs (pre-flight gates), Ticket entity, TicketAssignmentPolicy (the cross-epic
consumer: `dependencies: [auth:IUserRepository]`, body checks `auth:Role.AGENT`), ITicketRepository,
CreateTicket command, POST /tickets (authenticated). Validates OK 0/0/0 with `--app specs/epics`.

Scaffolder app-mode (FIRST multi-context run) added tickets into helpdesk4 alongside the filled auth
context: 26 tickets files; shared substrate regenerated from the union (exceptions.py +InvalidAssigneeError,
ValidationError deduped; containers.py wires ticket_assignment_policy(repo=user_repository) — the
cross-context DI; main.py includes both routers); `auth:IUserRepository` → `from hdk4.domain.auth import
IUserRepository`. Self-verify green.

Runner worklist: 7 tickets bodies across 3 DAG levels. Implementers filled them (5 level-0 in parallel,
then handler, then endpoint). Final gate: `mypy src tests` clean (94 files), ruff + format clean, 25
unit pass / 16 manual-skip, app constructs with OpenAPI over BOTH `/auth/login` and `/tickets`, worklist
drained. The discovery test auto-discovered `POST /tickets` as a protected route. The 4 pytest errors
are all DockerException (testcontainers — the known Docker-less integration gap), not failures.

KEY OUTCOME: the get_by_id delta (notes/11) now has its REAL consumer — TicketAssignmentPolicy calls
auth's get_by_id and type-checks against the real auth User/Role across subpackages. The cross-context
contract drift the runner trigger reconciles is now exercised for real, not just structurally.

OBSERVATIONS / SMALL DEBTS
--------------------------
- Scaffolder reordered Ticket entity fields (required before defaulted) — a legitimate declarative call
  (Python dataclass rule), not a manifest change.
- TicketRepository.add maps a PK IntegrityError to ValidationError because the tickets catalog has no
  ConflictError (only ValidationError + the auth errors + InvalidAssigneeError). If a ConflictError is
  added later, update the mapper. (A shared cross-context error catalog beyond ValidationError is a
  refinement.)
- Still model A only; signature-change drift still final-gate-only (notes/11); orphan GC / rename
  remain the unbuilt brownfield frontier (§4/§14).
