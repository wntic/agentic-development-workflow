что v2-фиксы держатся и не внесли регрессий; (б) более глубоким методом вычистить хвост.

МЕТОД. Workflow skill-altitude-audit-v3 (run wf_d8259a73-42d): на КАЖДЫЙ скилл ДВЕ независимые
линзы — A (fresh-eyes, полная 6-запаховая рубрика) + B (regression hunter: для 12 v2-правленых
скиллов — сводка что менялось + проверка полноты; для остальных — рассогласование от чужих правок).

cross_feature_coupling · scope_overclaim · layer_leak); guardrails расширены (pinned-tag-as-per-deployment
и illustrative-default-framed-as-non-universal — НЕ дефект).

V3-1  restapi-schema · optional_as_mandatory · HIGH
  Rule 7 «Always four fields … `items/total/limit/offset` … Do not paginate any other way» запрещает
  cursor-форму, которую сиблинги ПОДДЕРЖИВАЮТ: domain-filter Rule 5 (`cursor: str | None` вместо limit/offset,
  «Pick one»), restapi-endpoint (cursor-template строит `FooListResponse(items, next_cursor, limit)` + стр.156:
  «FooListResponse must match the chosen pagination shape — total/limit/offset OR next_cursor/limit»).
  → cursor-app по этому скиллу получает схему БЕЗ next_cursor и с лишними total/offset, ломающую свой роут.
  FIX: учить ОБЕ формы feature-conditionally; offset = items/total/limit/offset, cursor = items/next_cursor/limit;
       `*ListResponse` матчит pagination из domain-filter. Снять абсолют «Do not paginate any other way».
       Поправить и naming-table row.

V3-2  test-fake-repository · app_specific_literal · HIGH
  Rule 6 + CRUD-template: fake бросает `ConflictError("foo name already exists", {"constraint":"uq_foos_name","name":foo.name})`
  — ключ `name` в context, которого РЕАЛЬНЫЙ адаптер не ставит. infra-sqlalchemy-repository._map_integrity_error (стр.82)
  = `{"constraint": constraint}` ТОЛЬКО. Rule 6 сам требует копировать контракт «verbatim … same context keys» → само-
  противоречие. Тест на `exc.value.context["name"]` зелёный против fake, красный против реального адаптера (тот самый
  green-unit/red-integration trap, что fake призван предотвратить).
  FIX: убрать `name` из обоих ConflictError-вызовов (create+update) и из Rule-6 цитаты → `{"constraint":"uq_foos_name"}`;
       либо добавить `name` в _map_integrity_error первым (тогда обе стороны согласны).

V3-3  general-layered-architecture · wrong_altitude + app_specific_literal · HIGH
  (a) «Each core layer mirrors the same subdomain partition: domain/foos/, application/foos/, infrastructure/foos/»
  + step 4 «Implement each protocol as an adapter in infrastructure/<subdomain>/» — ИНФРА ГРУППИРУЕТСЯ ПО САБДОМЕНУ.
  Противоречит конвенции (conventions block A + CLAUDE.md): инфра группируется по ВНЕШНЕЙ ТЕХ (postgres/qdrant/openai/jwt),
  НЕ по сабдомену. Сгенерится неверное дерево, конфликт с infra-sqlalchemy-repository / infra-store-repository.
  (b) Диаграмма слоёв: «infrastructure/ … ORM models» — house-style = SQLAlchemy Core, НИКОГДА ORM.
  FIX: domain/application зеркалят сабдомен, infrastructure — по тех (`infrastructure/<kind|adapter>/`), указать на
       conventions block A; «ORM models» → «repositories/tables (SQLAlchemy Core)».

V3-4  test-discovery-invariants · optional_as_mandatory · HIGH
  test_unauth_returns_401.py эмитится БЕЗУСЛОВНО (one of «five files») с module-top импортами
  `from myapp.restapi.dependencies import get_current_user` + `from myapp.domain.exceptions import UnauthorizedError`.
  В auth-less app НЕТ ни dependencies.py (auth — единственный обитатель), ни UnauthorizedError → collection-time
  ImportError ломает ВЕСЬ tests/integration/api/ пакет. Скилл гейтит КАЖДУЮ другую опц-фичу (CORS/size/info — skip/drop),
  но не самый auth-зависимый файл. (Мой V2-11 добавил второй auth-only импорт, углубив уже бывшую негейченность.)
  FIX: гейтить весь файл на graph-derived auth-presence (как /info): auth есть → 5 файлов, нет → 4 (без 401-файла).
       Hard stop + смягчить «Produces five test files» → «four or five».

V3-12 domain-repository-protocol · optional_as_mandatory · MEDIUM — relational-only имплементер
  When-to-use + frontmatter: «concrete implementation in infrastructure/postgres/repositories/ → infra-sqlalchemy-repository»
  как ЕДИНСТВЕННЫЙ. Это чистый домен-скилл, протокол store-agnostic; client-store (qdrant/redis) → infra-store-repository под
  infrastructure/<store-kind>/repositories/ (conventions block B/C). Polyglot-читатель указан на неверного соседа + postgres-путь.
  FIX: соседа условно по store-профилю: «→ infra-sqlalchemy-repository (relational, postgres/) ИЛИ infra-store-repository
       (client-style, <store-kind>/); протокол сам store-agnostic». Зеркалить во frontmatter.

V3-13 test-application-handler · optional_as_mandatory · MEDIUM — `caller_id=_CALLER` не условно
  `_CALLER = uuid.uuid4()` (rule 2) + `caller_id=_CALLER` во ВСЕХ command-template (create/update/delete/comp-tx), без сигнала
  условности. Сиблинг application-command сделал caller_id auth-conditional (DTO rule 2: auth-free command «omits caller_id»).
  auth-less app: caller_id-поля в DTO нет → копипаст ломается.
  FIX: добавить тот же сигнал — templates показывают authenticated-форму; в auth-free app `caller_id=_CALLER` + сам `_CALLER`
       убираются (зеркалить application-command DTO rule 2). _CALLER оставить как authenticated-convention.

V3-14 pattern-compensating-tx · optional_as_mandatory · MEDIUM — success-log `caller_id` не условно
  Template success-log: `logger.info("foo_created", foo_id=..., caller_id=str(cmd.caller_id))` без условности. Этот скилл шейпит
  ТОТ ЖЕ handler-body, что application-command (уже починен). auth-less → cmd.caller_id не существует.
  FIX: убрать caller_id из примера ИЛИ аннотировать «caller_id only when the command carries it (authenticated) — see
       application-command DTO rule 2».

V3-15 conventions · optional_as_mandatory · MEDIUM — cryptography гейтится на auth-presence, а не на RS256/asymmetric
  Block D тянет `cryptography` «whenever the app declares auth», обосновывая RS256/RSA-keypair как канон. Но cryptography нужен
  ТОЛЬКО для асимметричного (RS256) генерирования/сериализации keypair. auth-app на HS256 (симметрик) имеет auth, но cryptography
  не импортит → reintroduce «stray dev-dep nothing imports» (то, что параграф сам предупреждает). Сиблинг
  test-integration-authed-client (rule 6) трактует RS256 vs HS256 как per-app prod-выбор.
  FIX: гейтить на asymmetric/keypair-схему (RS256/RSA), не на auth-presence; ИЛИ переформулировать RS256/RSA как «this app's
       scheme, not universal», отметив что HS256-auth-app не несёт cryptography. [ПРИМЕЧАНИЕ: каталог сейчас моделирует только
       RS256-auth → различие пока moot; правка — про снятие заморозки RS256-как-универсального, лёгкая.]

V3-16 test-principles · app_specific_literal · MEDIUM — «cross-org semantics» как универсальное

  FIX: «tenancy/authorization scoping (when the app declares it)» ИЛИ убрать; оставить универсальное (routing/DI/auth/validation).
